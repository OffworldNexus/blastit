# ROADMAP

Owned by the `strategist` (expensive tier). Other agents may **read** this file but must never alter milestone goals, versions, or exit criteria; propose adjustments via `uv run --no-project tools/plan.py --agent <you> human add "..."` or escalate to `strategist`.

**North Star (`docs/VISION.md`):** Everything in Blastit stems from **Developer Experience**. Every milestone and sub-release **must** begin by writing the lean, foolproof user documentation showing how it works on **(1) the local machine** (zero `sudo`), **(2) CI/CD** (guaranteed completeness — zero forgotten queries, routes, proxies, or input schemas), and **(3) deployments** (presets that fail closed) — critiqued through `dx` and `ai-ergonomics` goldfish lenses **before** internal design or Rust/Python implementation begins.

Milestones run in order (`MA` -> `MB` -> `MC` -> `MD`). Note that `v0.1.0` is already released (`2026-10-27`), so `MA` targets **`0.1.1`**, while `MB`, `MC`, and `MD` each span focused `0.2.x`, `0.3.x`, and `0.4.x` sub-releases.

## Standing policies

- **DX-First Iron Law:** Every milestone and feature epic MUST execute and review its user-facing documentation (`local`, `CI/CD`, `deployments`) through `dx` and `ai-ergonomics` goldfish critics **before** any technical design doc is finalized or production Rust/Python code is written.
- **Hard expensive-tier budget: `$100` (`plan/BUDGET.json`).** Enforced by `.opencode/plugins/autopilot`. Past 80 % of the cap, reserve Gemini 4 Carbon strictly for milestone gates and core architecture acceptances.
- **Soft escalation ratio:** ≤ 1 non-gate escalation per 15 completed tasks.
- **Release PRs & human merge gate:** Autonomous development happens on `release/<version>` branches (never pushing directly to `develop`). At each release boundary (`0.1.1`, `0.2.x`, `0.3.x`, `0.4.x`), once `make check` + `make e2e` + gate audits pass and `CHANGELOG.md` is dated, `conductor` pushes `release/<version>`, opens a GitHub PR into `develop`, and records a `HUMAN.md` review/merge checkpoint. A human merging that PR into `develop` validates `CI`, `Docs`, and `Live (DigitalOcean)` on `develop` and automatically publishes to PyPI and GitHub Releases (`publish-pypi.yml`).
- **Test curation:** Every code epic runs a `test-curator` audit; every milestone gate includes `cargo-mutants` on critical policy/validation crates.
