## Findings
**B1 BLOCKER — `slot_releasable` is `pub` in a private module, so the protected suite cannot name it.** §4.6:710 justifies `#[doc(hidden)] pub` "for the same reason as `open_with`: the protected suite compiles this crate as a dependency, where `pub(crate)` would be unreachable." But `lib.rs:70` is `mod scheduler;` and `lib.rs:85` re-exports only `{Emit, run}`; `open_with` is reachable only because it sits in `pub mod static_asset`. `tests/critical_rewrite.rs` therefore cannot call the oracle §4.6/§7.2 promise ("the oracle for the 'timeout while parked' arm that no unprivileged test can drive"), and MB.2.5.2's `paths` (NODE.md:9, §8:1072) are `scheduler.rs` + the test, so the fix is out of lane and §8's "No leaf needs an out-of-lane edit" is false. Fix: add `crates/blastit-scheduler/src/lib.rs` to MB.2.5.2 with one `#[doc(hidden)] pub use crate::scheduler::slot_releasable;` — or move the predicate's table to a `#[cfg(test)] mod` in `scheduler.rs` and drop the protected-suite claim. Until then the leaf is blocked at its own acceptance step.
**M1 MAJOR — the brief the implementer actually reads still contradicts §4.4/§4.6.** §8 records the drift but NODE.md is `status: ready`, and its `# Context` tells the implementer to keep `static_reads` ("with a bounded reader pool", line 23) and to run "resolve/`decide` … **before** `plan_request_body`" (line 24) — while §4.6 says "There is no `static_reads` counter" and §4.4 computes the plan in `begin_raw` and stores its error. Acknowledging drift does not stop the wrong implementation. Fix: resync the brief (or mark the node blocked) before it starts; drop the garbled `` `besides` `` token too.
**m1 MINOR — the stored `has_body` bool has no `Request` field.** §4.3 says `begin_raw` "stores only the resulting `bool`" and `decide` needs it in `dispatch_static`, but §4.6's gains list is `static_target`, `static_body`, `pumping`, `static_pending`. Name it (e.g. `static_has_body: bool`) there so the set stays exact.
**m2 MINOR — "set during resolution" collides with `Scheduler::resolve`.** §4.6 says `static_target` "is set during resolution"; the routing resolution is `self.resolve(&head)` in `begin_raw`, while the file resolution is the step 5–11 `resolve` in `dispatch_static`. Say "inside `dispatch_static`", or a reader may open a descriptor before the slot exists, contradicting §4.6's own no-fd-before-slot rule.
**m3 MINOR (M1 residual) — the helper must restate `respond`'s bookkeeping.** `respond` (`scheduler.rs:2567`) takes no extra headers but sets `head_sent`, `status`, `bytes_out`, `mark_finished`. A helper that builds its own `RespHead` to add `Allow`/`no-store` can make the `request` event's `bytes_out`/duration diverge; prefer "the helper calls `respond` extended with an `extra: &[(&[u8], &[u8])]` slice" so one writer keeps the event shape.

No §4.3/§4.6 ordering, §4.4/§4.5, or `has_app = RouteInfo.static_forward` contradiction: `route.rs:67` computes `policy && !spa && has_app` and `decide` reads it only in the `Missing` arm. `decide` needs no `rewrite.rs`/`route.rs` change.
VERDICT: FAIL
