# Goal

Turn the two `MA` gate negatives into permanent `e2e/` assertions — a `queries = []` denying listener (SQLSTATE `42501`) and an unprivileged `--cap-drop ALL` negative boot that must exit `1` naming the missing capabilities — and remove the timing race in `python/tests/critical/test_check_contract.py`'s learn-refusal test without relaxing a single assertion.

# Context

- `plan/nodes/MB/NODE.md` items 5 and 6. Today the denial is only proven incidentally (a route whose grant lacks a statement, `e2e/scenario.py:637`); an explicitly empty grant (`queries = []`) is a different listener configuration and is not asserted. `queries = []` is a valid manifest (`crates/blastit-manifest/tests/parse.rs`).
- The negative boot is a product contract (`blastit` fails closed without root/capabilities) that only CI-time `smoke (root)` covers today; `e2e/rootless/run.py` proves the positive capability path, not the refusal.
- `python/tests/critical/test_check_contract.py::test_learn_refuses_an_inline_literal_with_exit_one_and_writes_nothing` occasionally asserts `server.statements` before the view has drained the last statement: the suite's own server object is read at exit. This node's `paths` list that protected file **only** to remove the race (wait for the refusal line / drain before asserting). Deleting, skipping or weakening an assertion is a hard FAIL.
- `e2e/demo/blastit.toml` is generated by `e2e/grants.py` from a scenario harvest and then committed: teach the generator to emit and keep the empty grant, or it will be dropped on the next regeneration.

# Acceptance

```console
$ uv run --no-project e2e/scenario.py --self-test

# 2. Full e2e (builds the wheel, runs Docker, root and rootless) — the new checks must print PASS.
$ CARGO_NET_OFFLINE=true UV_OFFLINE=1 make e2e
#   quote the new lines, e.g. "PASS: ... queries = [] listener denies with 42501"
#   and "PASS: ... --cap-drop ALL boot exits 1 naming cap_setpcap"

# 3. The learn-refusal test is deterministic: three consecutive clean critical runs.
$ for i in 1 2 3; do CARGO_NET_OFFLINE=true UV_OFFLINE=1 make test-critical || break; done

# 4. The protected-file diff is a race fix and nothing else.
$ git diff -U3 -- python/tests/critical/test_check_contract.py
#   only ordering/wait/drain lines; the assertions are byte-identical

# 5. Guard agrees this node may touch that file.
$ uv run --no-project tools/critical_guard.py        # exit 0
```

# Notes

- New denial route: a `[[route]]` with a `[route.db]` that declares `queries = []` and no group; the app sends one ordinary statement on it and the scenario asserts the proxy's `42501` (`sql.denied` event and/or the app-visible error), never a database-level permission error.
- Negative boot must assert the **message**, not just the exit code: `init runs as uid 10000 and is missing cap_...` (see the troubleshooting table). Run it against the same prebuilt image the rest of `e2e/` uses.
- If Docker is unavailable on this host, stop and report `BLOCKED` with `docker info` output — do not stub the container checks or mark them skipped (a skip in this tree fails `critical-skip-check`).
- Keep `e2e/` assertions permanent and offline-safe: no network calls, no `sleep`-based waits, deterministic ports (they already come from `E2E_PORT`/`E2E_SQLALCHEMY_PORT`).
