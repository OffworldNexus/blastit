# RESULT MB.1.8

Permanent `e2e/` empty-grant and negative-boot assertions, plus the deterministic
learn-refusal test. `make e2e` (one run) and three consecutive `make test-critical`
runs are green; the protected file's diff is a wait and nothing else.

## Summary

**The `queries = []` denying listener is a permanent e2e assertion.** A new
`/deny/sql/` route in the demo manifest declares `[route.db] queries = []` and
takes **no group**, so blastit binds it a listener whose allowlist is empty
(`route_declares_proxy` is true, `effective_grants` is empty — the
"declared-but-empty" path in `stage0::bind_view_sockets`). The demo view
`notes.views.deny_sql` runs one ordinary statement — `SELECT count(*) FROM
notes_note`, the statement the `sql` route *is* granted — over a plain psycopg
connection in autocommit mode (Django's own connection would send its
`set_config('TimeZone', …)` housekeeping first, and a refusal of *that* would
not prove anything about the statement). `e2e/scenario.py` asserts the
app-visible `sqlstate == "42501"` from the `deny` process, and
`e2e/check_logs.py` asserts the cause: a `sql.denied` event on route `deny`
whose `reason` is `the statement is not granted` and whose `sqlstate` is
`42501` — the allowlist's refusal, not a database permission error (which never
produces a `sql.denied` line at all).

The manifest is generated by `e2e/grants.py`, so the generator had to learn the
shape or a regeneration would silently drop it:

* `EMPTY_GRANT = {"deny"}` is written as `[route.db]` + `queries = []`, and its
  route gets no `groups` line;
* every other route now attaches `groups = ["connection"]` **itself** instead of
  taking it from the top-level `groups` key — the top-level key attaches a group
  to *every* route, which would hand `deny` the connection statements and turn
  the empty listener into a two-statement one. (This is also the `docs/`
  preferred form: `reference/manifest.md` §Groups.)
* the deny path is in `DENY_PATHS`, so a harvest of it can never grant anything;
* drive-by: `/debug/request/` was missing from `ROUTES` although the committed
  manifest routed it to `debug` — a regeneration would have sent it to
  `fallback` (and failed `check_logs.py`). Added.

**The unprivileged negative boot is a permanent Docker assertion.**
`e2e/rootless/run.py` gains `check_negative_boot(image)`: the image the rootless
stack just built, run with `--cap-drop ALL` as uid 10000, must exit `1` **and**
print `init runs as uid 10000 and is missing cap_chown, cap_dac_override,
cap_fowner, cap_kill, cap_setgid, cap_setuid` (the sentence
`docs/troubleshooting.md` sends that deployment to). It starts the **shared**
interpreter: the image's default command is the capable `*-init` copy, and with
an empty bounding set the kernel will not even `execve` it (`Operation not
permitted`), which is a deployment error but not the message an operator has to
be told.

**The learn-refusal test is deterministic without weakening an assertion.** The
only change in the protected file is a bounded wait before the existing
`server.statements` assertion, plus `import time`: the wire statement, the
observation drain and the report are three asynchronous stages, so the test now
waits (≤ 10 s) for the statement to be on its own mock server before asserting
what reached it. Every assertion is byte-identical; a timeout only means the
assertion fails with the message it always had. 20 local repeats of the single
test (15 before the change, 5 after) and the three full critical runs were clean.

## Follow-ups

1. **`docs/` (out of scope here):** a LESSONS entry is worth having — *a
   file-capability copy cannot be `execve`d at all when its capabilities are
   outside the bounding set (`EPERM`, "Operation not permitted"), so a
   `--cap-drop ALL` negative boot has to start the shared interpreter; testing
   the capable copy would assert the runtime's error, not blastit's.*
2. **Droplet path:** `check_negative_boot` runs in the local driver only (the
   droplet run's image lives on the droplet). If the droplet run should assert
   the refusal too, it needs an `ssh_run(..., "docker run …")` twin; `make e2e`,
   the CI path, covers the local one.
3. **`pg.refused` carries `proxy`, not `route`** (`blastit-events`), so the log
   assertion for "the proxy refused, not the database" is the `sql.denied`
   reason/sqlstate pair — a `pg.refused` line is a refused *connection*, and
   asserting on a `route` field there would have been vacuous.
4. **`e2e/demo/blastit.toml` is still regenerated by hand here** (no harvest
   file exists offline). Its shape now matches `grants.py` exactly (route names,
   paths, methods, groups, `transaction_control`, egress, and the empty grant),
   so the next `uv run e2e/grants.py /tmp/harvest.jsonl` will not drop the deny
   route — but a real harvest re-run before 0.2.0 is worth one diff.
5. **The edit hook runs `ruff format` on every Python file it touches**, so
   `e2e/` files that are not formatted today reflowed on first edit. The diff
   was rebuilt by hand on top of `HEAD` to keep it to the change (verified:
   `git diff --stat -- e2e/` shows 204 insertions across 9 files, no
   whole-file reflow); a future node that edits `e2e/` should expect the same, or the tree should
   adopt `e2e/` in `make py-format`.
