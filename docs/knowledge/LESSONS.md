# Lessons Learned (`docs/knowledge/LESSONS.md`)

Append one concise bullet whenever you hit a non-obvious environment, Linux privilege, Rust/PyO3, WASM, or Zensical gotcha. Read relevant entries before starting work in that area.

- **PyO3 test binaries & `libpython`:** System `/usr/bin/python3` on this host is 3.10 without a shared `libpython` on default `LD_LIBRARY_PATH`, while Blastit targets CPython >= 3.13. Always run Cargo clippy/doc/test with `PYO3_PYTHON="$(uv python find '>=3.13')"` and `LD_LIBRARY_PATH` pointing to that interpreter's `../lib` directory — `Makefile` (`make check`, `make rs-test`, `make rs-lint`) sets both automatically.
- **PyO3 embedded interpreter needs `PYTHONHOME` at runtime:** `PYO3_PYTHON` + `LD_LIBRARY_PATH` are enough to link and load `libpython3.X.so`, but a Rust test binary that *embeds* CPython (e.g. `blastit::immortal`) also needs `PYTHONHOME` set to the interpreter's **install prefix** (the parent of its `bin/`, i.e. the directory whose `lib/` is already on `LD_LIBRARY_PATH`). Without it the binary aborts on startup with `Could not find platform independent libraries <prefix>` / `ModuleNotFoundError: No module named 'encodings'`. The `Makefile` derives `PYO3_PREFIX := $(dir $(PYO3_BIN))/..` and exports it as `PYTHONHOME` inside the shared `RUST_ENV`, so never hardcode a host path.
- **Offline / zero-project `uv` execution:** Root `pyproject.toml` uses the `blastit_build` maturin PEP 517 backend, so bare `uv run` rebuilds the wheel. For standalone scripts (`tools/*.py`, `e2e/*.py`), always use `uv run --no-project ...`, and for cached CLI tools (`ruff`, `zensical`) use `uvx --offline ...` so commands finish in milliseconds without touching PyPI.
- **Zensical `exclude_docs`:** `zensical.toml` builds `docs/` with `--strict` link/anchor validation. Internal agent directories (`VISION.md`, `design/`, `decisions/`, `research/`, `knowledge/`, `testing/`) are listed in `exclude_docs` so they never leak into the public documentation site or break `--strict`.
- **Zensical Mermaid shadow DOM:** Zensical renders `<pre class="mermaid">` diagrams inside a **closed shadow root**. `document.querySelector('svg')` cannot see them; visual screenshot inspection (`visual-checker` `take_screenshot`) is the only honest way to verify rendered diagrams.
- **gVisor `SO_PEERCRED` & `/proc/<pid>/environ`:** Under DigitalOcean App Platform's gVisor sentry, `SO_PEERCRED` returns the *listener's* credentials rather than the client's (use per-route `0600` listeners in `0700` dirs + `SO_PASSCRED`/`SCM_CREDENTIALS`), and `/proc/<pid>/environ` is `0444` across UIDs even with `PR_SET_DUMPABLE(0)` (so the stage-0 `execve` barrier with empty env for brokers and swapped env for stage 1 is mandatory).
- **`obs_fd` writers block their session:** dbproxy writes each `WireSqlObs` line synchronously under a mutex into the descriptor it was handed. A Unix socketpair's buffer is only a couple of hundred KiB, so an orchestrator (or a test) that stops draining `obs_fd` while a suite runs ends up blocking the view's statement task, not just dropping observations. Drain it on its own task, and treat a write error as "the reader is gone" (dbproxy then drops the sink instead of retrying per statement).
- **AF_UNIX stream sockets turn "end of file" into `ECONNRESET`:** when a peer exits with messages still queued in *its* receive buffer (a `DRAIN` it never read, or an `EXITED` written after it left), the other end's next `read(2)` returns `ECONNRESET` (`Connection reset by peer`, os error 104) instead of `0`. A supervisor that only treats `read == 0` as "the scheduler is gone" therefore turns a clean `SIGTERM` into exit `1` under load; classify `EPIPE`/`ECONNRESET` as a lost peer on **both** the read and the write side (MA.2.3.8, audit F4).
- **A `COPY` glob that matches nothing blames the directory:** `COPY dist/blastit-*-cp313-*.whl /tmp/dist/` on a host whose wheel is `cp314` fails the whole build with `failed to solve: lstat /dist: no such file or directory` — the sentence names `dist`, not the pattern, so it reads like a missing directory rather than a version mismatch. Copy the directory (`COPY dist/ /tmp/dist/`) and let a `count` check say which wheels are there; and remember that a non-abi3 wheel's `cp3NN` tag *is* the interpreter it needs, so a prebuilt image's `FROM python:` has to follow the wheel's tag (the e2e drivers read it in `e2e/prebuilt_wheel.py`) instead of pinning 3.13 (MA.2.3.13).
- **A rebuilt local wheel is invisible to `uv`'s cache:** `uv pip install --find-links dist blastit`, and the runnable-docs harness's `uv sync` (it uses the global `uv cache dir`), can reinstall the wheel cached for the same path and file name even after `dist/blastit-<version>.whl` was rebuilt from new sources — a product change then hides behind a stale `_blastit*.so` for a whole `make docs-test` run (the first post-fix run still showed the old `503 queue_timeout`, and the second still showed attempt 1's raw-percentage refusal). Check which artifact ran (`sha256sum`, or `strings` for a message only the new build has) and use `uv cache clean blastit --force` or `uv pip install --no-cache` after `scripts/build-wheel.sh` (MA.3.7).
- **cgroup v2 `memory.current` is not "memory in use":** it counts the page cache the kernel reclaims on demand, so a watermark compared against it refuses to boot a healthy machine — on a 48 GiB runner at ~46 GiB `memory.current` (96 %) the kernel still has ~12 GiB `MemAvailable`. Subtract what the kernel gives up: `(file − shmem − file_mapped) + slab_reclaimable` from `memory.stat` (`inactive_file` alone is not enough: it left the same host at 85–88 %), never `shmem`/tmpfs, which is unreclaimable without swap and was ~29 GiB here. The identity `memory.current ≈ anon + file + kernel` is what makes the split checkable against `MemTotal − MemAvailable`. Pinned in `crates/blastit/src/mem_usage.rs` (MA.3.7 attempt 2).
- **A `make docs-test` run can silently test yesterday's binary:** the runnable-docs harness takes its `UV_CACHE_DIR` from the global `uv cache dir`, and `uv sync` reuses the wheel cached for the same version and file name, so a rebuilt `dist/blastit-0.1.0-*.whl` hides behind the old `_blastit*.so` for a whole gate run (symptom: fences show the *previous* message, on a host whose `memory.current` is 96 % the dev fences are still red after the fix). `uv cache clean blastit --force` before the run, or give the harness a per-run cache; check with `strings dist/.../blastit/_blastit*.so` for a string only the new build has.
- **An above-watermark host makes every `blastit dev` fence red, by design:** the scheduler cannot start a view above `BLASTIT_MEM_HIGH_WATERMARK` and there is nothing to evict yet, so `blastit dev` refuses at boot with `blastit dev: memory: <used> of <total> used (<p>%) is above BLASTIT_MEM_HIGH_WATERMARK (<n>%)…` (exit 1, empty stdout) instead of serving silent `503`s. Nothing needs to inject a knob to make the fences green: with the reclaim-aware reading above, a 48 GiB runner at ~76 % boots and serves with no `BLASTIT_*` at all (MA.3.7).
- **`CARGO_NET_OFFLINE=1` breaks maturin, not cargo:** cargo accepts `1` for `CARGO_NET_OFFLINE`, but maturin ≥ 1.16 parses the variable as a strict bool when it shells out to cargo, so `CARGO_NET_OFFLINE=1 UV_OFFLINE=1 make check` dies in `docs-test` → `scripts/build-wheel.sh` with `failed to parse environment variable CARGO_NET_OFFLINE / provided string was not 'true' or 'false'` after every plain-cargo target has passed. Use `CARGO_NET_OFFLINE=true` for a full gate run (MA.3.6).
- **A full `/tmp` tmpfs shows up as a linker bus error:** with `/tmp` at 100 % (stale `cargo-mutants`/target dirs under `/tmp/opencode`), `cargo test --workspace --doc` fails with `collect2: fatal error: ld terminated with signal 7 [Bus error]` and "Couldn't compile the test", which reads like a broken doctest rather than no space; `df -h /tmp` first, then clear old target dirs (MA.3.6).
- **A clean `git merge-tree` can still be a semantic merge disaster:** when two branches rewrite the *same function* into differently-shaped versions (this branch added an early-answer path to `Conn::relay`; the perf branch split `relay` into `relay` + `relay_frames`), git merges the hunks it can and leaves a chimera that parses, type-checks in unrelated places, and silently drops one side's invariants — `merge-tree --write-tree` listed 2 conflicts while `blastit-events/src/json.rs` had a develop-only line calling helpers the perf rewrite had deleted. Read the *whole* `git diff` of every file both sides touched, compile early, and treat every "both changed" file as a manual union, not a resolved hunk (MA.6).
