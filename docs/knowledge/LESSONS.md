# Lessons Learned (`docs/knowledge/LESSONS.md`)

Append one concise bullet whenever you hit a non-obvious environment, Linux privilege, Rust/PyO3, WASM, or Zensical gotcha. Read relevant entries before starting work in that area.

- **PyO3 test binaries & `libpython`:** System `/usr/bin/python3` on this host is 3.10 without a shared `libpython` on default `LD_LIBRARY_PATH`, while Blastit targets CPython >= 3.13. Always run Cargo clippy/doc/test with `PYO3_PYTHON="$(uv python find '>=3.13')"` and `LD_LIBRARY_PATH` pointing to that interpreter's `../lib` directory — `Makefile` (`make check`, `make rs-test`, `make rs-lint`) sets both automatically.
- **PyO3 embedded interpreter needs `PYTHONHOME` at runtime:** `PYO3_PYTHON` + `LD_LIBRARY_PATH` are enough to link and load `libpython3.X.so`, but a Rust test binary that *embeds* CPython (e.g. `blastit::immortal`) also needs `PYTHONHOME` set to the interpreter's **install prefix** (the parent of its `bin/`, i.e. the directory whose `lib/` is already on `LD_LIBRARY_PATH`). Without it the binary aborts on startup with `Could not find platform independent libraries <prefix>` / `ModuleNotFoundError: No module named 'encodings'`. The `Makefile` derives `PYO3_PREFIX := $(dir $(PYO3_BIN))/..` and exports it as `PYTHONHOME` inside the shared `RUST_ENV`, so never hardcode a host path.
- **Offline / zero-project `uv` execution:** Root `pyproject.toml` uses the `blastit_build` maturin PEP 517 backend, so bare `uv run` rebuilds the wheel. For standalone scripts (`tools/*.py`, `e2e/*.py`), always use `uv run --no-project ...`, and for cached CLI tools (`ruff`, `zensical`) use `uvx --offline ...` so commands finish in milliseconds without touching PyPI.
- **Zensical `exclude_docs`:** `zensical.toml` builds `docs/` with `--strict` link/anchor validation. Internal agent directories (`VISION.md`, `design/`, `decisions/`, `research/`, `knowledge/`, `testing/`) are listed in `exclude_docs` so they never leak into the public documentation site or break `--strict`.
- **Zensical Mermaid shadow DOM:** Zensical renders `<pre class="mermaid">` diagrams inside a **closed shadow root**. `document.querySelector('svg')` cannot see them; visual screenshot inspection (`visual-checker` `take_screenshot`) is the only honest way to verify rendered diagrams.
- **gVisor `SO_PEERCRED` & `/proc/<pid>/environ`:** Under DigitalOcean App Platform's gVisor sentry, `SO_PEERCRED` returns the *listener's* credentials rather than the client's (use per-route `0600` listeners in `0700` dirs + `SO_PASSCRED`/`SCM_CREDENTIALS`), and `/proc/<pid>/environ` is `0444` across UIDs even with `PR_SET_DUMPABLE(0)` (so the stage-0 `execve` barrier with empty env for brokers and swapped env for stage 1 is mandatory).
- **`obs_fd` writers block their session:** dbproxy writes each `WireSqlObs` line synchronously under a mutex into the descriptor it was handed. A Unix socketpair's buffer is only a couple of hundred KiB, so an orchestrator (or a test) that stops draining `obs_fd` while a suite runs ends up blocking the view's statement task, not just dropping observations. Drain it on its own task, and treat a write error as "the reader is gone" (dbproxy then drops the sink instead of retrying per statement).
- **AF_UNIX stream sockets turn "end of file" into `ECONNRESET`:** when a peer exits with messages still queued in *its* receive buffer (a `DRAIN` it never read, or an `EXITED` written after it left), the other end's next `read(2)` returns `ECONNRESET` (`Connection reset by peer`, os error 104) instead of `0`. A supervisor that only treats `read == 0` as "the scheduler is gone" therefore turns a clean `SIGTERM` into exit `1` under load; classify `EPIPE`/`ECONNRESET` as a lost peer on **both** the read and the write side (MA.2.3.8, audit F4).
- **A `COPY` glob that matches nothing blames the directory:** `COPY dist/blastit-*-cp313-*.whl /tmp/dist/` on a host whose wheel is `cp314` fails the whole build with `failed to solve: lstat /dist: no such file or directory` — the sentence names `dist`, not the pattern, so it reads like a missing directory rather than a version mismatch. Copy the directory (`COPY dist/ /tmp/dist/`) and let a `count` check say which wheels are there; and remember that a non-abi3 wheel's `cp3NN` tag *is* the interpreter it needs, so a prebuilt image's `FROM python:` has to follow the wheel's tag (the e2e drivers read it in `e2e/prebuilt_wheel.py`) instead of pinning 3.13 (MA.2.3.13).
- **A rebuilt local wheel is invisible to `uv`'s cache:** `uv pip install --find-links dist blastit`, and the runnable-docs harness's `uv sync` (it uses the global `uv cache dir`), can reinstall the wheel cached for the same path and file name even after `dist/blastit-<version>.whl` was rebuilt from new sources — a product change then hides behind a stale `_blastit*.so` for a whole `make docs-test` run (the first post-fix run still showed the old `503 queue_timeout`, and the second still showed attempt 1's raw-percentage refusal). Check which artifact ran (`sha256sum`, or `strings` for a message only the new build has) and use `uv cache clean blastit --force` or `uv pip install --no-cache` after `scripts/build-wheel.sh` (MA.3.7).
- **cgroup v2 `memory.current` is not "memory in use":** it counts the page cache the kernel reclaims on demand, so a watermark compared against it refuses to boot a healthy machine — on a 48 GiB runner at ~46 GiB `memory.current` (96 %) the kernel still has ~12 GiB `MemAvailable`. Subtract what the kernel gives up: `(file − shmem − file_mapped) + slab_reclaimable` from `memory.stat` (`inactive_file` alone is not enough: it left the same host at 85–88 %), never `shmem`/tmpfs, which is unreclaimable without swap and was ~29 GiB here. The identity `memory.current ≈ anon + file + kernel` is what makes the split checkable against `MemTotal − MemAvailable`. Pinned in `crates/blastit/src/mem_usage.rs` (MA.3.7 attempt 2).
- **A `make docs-test` run can silently test yesterday's binary:** the runnable-docs harness takes its `UV_CACHE_DIR` from the global `uv cache dir`, and `uv sync` reuses the wheel cached for the same version and file name, so a rebuilt `dist/blastit-0.1.0-*.whl` hides behind the old `_blastit*.so` for a whole gate run (symptom: fences show the *previous* message, on a host whose `memory.current` is 96 % the dev fences are still red after the fix). `uv cache clean blastit --force` before the run, or give the harness a per-run cache; check with `strings dist/.../blastit/_blastit*.so` for a string only the new build has.
- **An above-watermark host makes every `blastit dev` fence red, by design:** the scheduler cannot start a view above `BLASTIT_MEM_HIGH_WATERMARK` and there is nothing to evict yet, so `blastit dev` refuses at boot with `blastit dev: memory: <used> of <total> used (<p>%) is above BLASTIT_MEM_HIGH_WATERMARK (<n>%)…` (exit 1, empty stdout) instead of serving silent `503`s. Nothing needs to inject a knob to make the fences green: with the reclaim-aware reading above, a 48 GiB runner at ~76 % boots and serves with no `BLASTIT_*` at all (MA.3.7).
- **`CARGO_NET_OFFLINE=1` breaks maturin, not cargo:** cargo accepts `1` for `CARGO_NET_OFFLINE`, but maturin ≥ 1.16 parses the variable as a strict bool when it shells out to cargo, so `CARGO_NET_OFFLINE=1 UV_OFFLINE=1 make check` dies in `docs-test` → `scripts/build-wheel.sh` with `failed to parse environment variable CARGO_NET_OFFLINE / provided string was not 'true' or 'false'` after every plain-cargo target has passed. Use `CARGO_NET_OFFLINE=true` for a full gate run (MA.3.6).
- **A full `/tmp` tmpfs shows up as a linker bus error:** with `/tmp` at 100 % (stale `cargo-mutants`/target dirs under `/tmp/opencode`), `cargo test --workspace --doc` fails with `collect2: fatal error: ld terminated with signal 7 [Bus error]` and "Couldn't compile the test", which reads like a broken doctest rather than no space; `df -h /tmp` first, then clear old target dirs (MA.3.6).
- **A clean `git merge-tree` can still be a semantic merge disaster:** when two branches rewrite the *same function* into differently-shaped versions (this branch added an early-answer path to `Conn::relay`; the perf branch split `relay` into `relay` + `relay_frames`), git merges the hunks it can and leaves a chimera that parses, type-checks in unrelated places, and silently drops one side's invariants — `merge-tree --write-tree` listed 2 conflicts while `blastit-events/src/json.rs` had a develop-only line calling helpers the perf rewrite had deleted. Read the *whole* `git diff` of every file both sides touched, compile early, and treat every "both changed" file as a manual union, not a resolved hunk (MA.6).
- **Django re-states the session `TimeZone` at connect; the server's spelling decides the grant:** `postgresql/base.py::_configure_timezone` sends `SELECT set_config('TimeZone', $1, false)` when the startup zone isn't Django's `UTC` — `postgres:18` says `Etc/UTC`, so `blastit check` flags `missing_grant` on the connecting route; `postgres:15-alpine` says `UTC`, so a grant there is a `dead_grant` error (`fix.remove_query`, `unsafe: true`). Fixtures must ask the server (`psycopg` `connection.info.parameter_status("TimeZone") == "UTC"` → no grant, per `_django_manifest()` in `python/tests/test_check.py`), never "just grant it": an unused grant is an error. Apps attach one `groups = ["connection"]` to every route (`reference/manifest.md` §Groups), since it runs on whichever route opens the connection; `check` names exactly that — `fix.action: add_group`, `to: "[group.connection.<proxy>].queries"` — for connection-setup SQL only, and keeps `add_query` for per-route statements (`SELECT 1` included, `MB.1.6`).
- **An SVG served as an `<img>` must stay well-formed XML, and `zensical build --strict` will not tell you:** a literal `<img>` inside the `/* … */` banner comment of a `style` block opens an unclosed `img` element, so the whole asset decodes to `naturalWidth 0` (the page shows alt text) while `make docs-check` still says "No issues found" — parse it (`xml.etree.ElementTree.parse`) and check a browser renders it, and write `&lt;img&gt;`. Its asset-level `@media (prefers-color-scheme: …)` rules *do* apply inside an `<img>` in Chromium, so a logo that needs two schemes lives in one file and needs no page CSS (MB.1.7).
- **An allocation oracle must compare *second* passes in separate worlds, with a per-thread armed flag:** the first measured 100-request pass in a fresh `World` allocates ~23.6 per request while every pass after it allocates ~66.02, because the client's flow tables and the scheduler's maps are still growing — so measuring one pass in each of two worlds silently compares a cold world against a warm one and the delta you "prove" is the warm-up, not your change. Warm both worlds, measure each one's *second* pass, and keep `ARMED`/`ALLOCS` in `thread_local!` (a global `AtomicBool` lets two parallel tests in the same binary disarm each other's measurement — one `#[global_allocator]` is fine, one shared flag is not). `crates/blastit-scheduler/tests/head_allocs.rs` (`MB.1.6`).
- **A production stage-0 error is an `app.output` event on *stdout*, not stderr:** `stage0::run` surfaces startup output as `{"event":"app.output","stream":"stderr","line":"…"}` JSON on fd 1 (`stage0.rs`), so a test that greps `err.txt` for `./blastit.toml: No such file or directory` in production mode reads 0 bytes and reports "the message is missing" — while `blastit dev` writes the same sentence to fd 2. Read the right stream on each side of the capability gate, and remember an unprivileged production boot is refused *before* `Config::from_env`, so it never reaches the manifest at all: that leg needs root or `blastit dev`. `MB.1.6`.
- **`cargo-mutants` 27.1.0 never writes `outcomes.txt`:** it writes `mutants.out/{caught,missed,timeout,unviable}.txt` plus `mutants.json` and `outcomes.json` (one JSON list with every mutant's `scenario`/`summary`), so the `awk '$NF=="caught"' outcomes.txt` ratio one-liners in older plan acceptance blocks never ran at all — `awk` cannot open its input, printed nothing, and the absent ratio read as "no misses". Recompute ratios from the per-outcome files (`wc -l mutants.out/{caught,missed,timeout,unviable}.txt`) or `outcomes.json`; the `MB.1.2`–`MB.1.5` acceptance snippets are already corrected (`MB.1.1`).
- **Two concurrent `cargo mutants` runs must not share `MUTANTS_TMP`:** `cargo-mutants` 27.1.0 scratch-copies the workspace into `$TMPDIR/cargo-mutants-<crate>-XXXX.tmp` and deletes stale copies under that parent on start, so a leaf that runs `rm -rf /tmp/opencode/blastit-mutants/cargo-mutants-*.tmp` (or just starts a second run) kills the other one mid-build with `ERROR Worker thread failed: "…/src/<file>.rs" does not exist, refusing to create it` after a perfectly good baseline — the message names a source file, not the scratch dir that vanished. Give every parallel leaf its own `make mutants-rust PKG=… MUTANTS_TMP=/tmp/opencode/<node>-mut-tmp`, and only drop that override when nothing else is running (MB.1.2).
- **A loop step written as `i += 1` is not merely untested — one of its mutants can never be killed:** `cargo mutants` rewrites it to `i *= 1`, the cursor then never advances, and the mutant is reported `TIMEOUT` (in the killed-ratio denominator, where no test can ever fail on it) while the same class in `code_token`'s `i + 1 → i * 1` returns `end == i` and only gets caught because the caller pushes an empty token per iteration until the process aborts on a 128 MiB allocation — an OOM abort racing a 90 s cap, not evidence. Rewrite the scan so the *iterator* is the step (`for (i, &c) in text.iter().enumerate()` plus a `resume` index that only marks how much of the region is already written): every mutant then terminates and fails a real assertion in ~1 s, and the crate clears the bar with 0 timeouts (`crates/blastit-sqlpolicy/src/normalize.rs`, `MB.1.4`).
- **`rustfmt --edition 2024 <file>` is not `cargo fmt`:** the standalone call sorted `use crate::lexer::{RegionKind, is_space, lex}` into `{is_space, lex, RegionKind}` (ASCII order) while `cargo fmt --all -- --check` demanded the style-edition-2024 version order (`{RegionKind, is_space, lex}`), so a file that "rustfmt passed" was still red in `make rs-fmt` — format and check with `cargo fmt --all [-- --check]` (cargo passes the package's `style_edition` from `edition`) and never run a bare `rustfmt` inside this workspace (`MB.1.5`).
- **`/tmp` is tmpfs here, so a `cargo-mutants` scratch dir spends RAM, not disk — and the campaign needs a cgroup cap:** `/tmp` is a 32 GiB tmpfs, and `cargo-mutants` copies the workspace per job into `$TMPDIR/cargo-mutants-<crate>-XXXX.tmp` and builds every mutant there. Measured on a 2-job `blastit-env` campaign (174 mutants): 2.2 GB of scratch copies at peak (a copy holds its own `target/`) and 2.9 GiB of `memory.peak` inside the campaign's scope; an interrupted run leaves those copies behind, and the old `/tmp/opencode` default meant four campaigns quietly ate RAM. `Makefile` now starts every campaign from `$(XDG_CACHE_HOME:-$HOME/.cache)/blastit-mutants` (disk; `make -s print-mutants-tmp`, or override `MUTANTS_TMP=/var/tmp/blastit-mutants`), prunes `mutants.out` plus stale copies (retention `MUTANTS_KEEP_SCRATCH=2`, never a copy touched within `MUTANTS_STALE_MIN=240`), refuses to start below `MUTANTS_MIN_FREE_GB=5` free on that filesystem, and runs under `systemd-run --user --scope -p MemoryMax=$(MUTANTS_MEMORY_MAX)` (12G: ~4x the measured peak) `-p MemorySwapMax=0`. Prove the cap with `make mutants-scope-probe` — from inside the scope `/proc/self/cgroup` names `run-<pid>-<n>.scope` and `/sys/fs/cgroup<path>/memory.max` is exactly `12884901888` for 12G; a host without a usable user manager (container/CI) or `BLASTIT_MUTANTS_NO_SCOPE=1` logs `memory cap: none (fallback: …)` and runs the plain command. `make mutants-clean` frees the whole scratch in one step — never while a campaign runs, because cargo-mutants' own stale-copy cleanup is what turns a vanished scratch into `ERROR Worker thread failed: "…/src/<file>.rs" does not exist` after a good baseline; for the same reason keep one campaign per checkout, since every run owns the same `mutants.out` (`MB.1.11`).
- **A git worktree under `/tmp` is the same defect class as a mutants scratch:** a release worktree checked out under `/tmp` (tmpfs) held 12 G of RAM, and `$HOME` has the same "disk you forgot you were spending" problem. Keep them inside the checkout on disk: `git worktree add .worktrees/<slug> <branch>` and `git worktree remove .worktrees/<slug>`, with `/.worktrees/` in `.gitignore`. `tools/guard.py` inspects `git status --porcelain --untracked-files=all`, which never lists ignored paths, so a present checkout does not trip the >5 MiB / stray-binary rules: guard reported the identical `OK (19 …)` with and without `.worktrees/hygiene-check` and `make check` stayed green (`MB.1.11`).
- **A numeric literal read one character short is invisible in the normalised text:** the 21 `number_end` survivors in `crates/blastit-sqlpolicy/src/lexer.rs` all split one number into two adjacent tokens (`0x1` → `0x` + `1`), and `normalize` copies code verbatim, so the output — and every text-level assertion — is byte-identical and no text test can kill them. Assert the *index* (`number_end(chars, 0) == Some(5)` for `0x1_2`), and through the public API assert the one place the boundary is observable: whether the character behind the literal starts a *fresh* token, so a following `$1` is a bind parameter (`0x_$1` → `0x_$?`, while `0x__$1` and `1_$1` keep it as identifier data) and an `E` opens an E-string (`1..E'a\'b  c'` keeps both spaces) unless `integer_junk` glued it to the number (`0x1E'a\'b  c'` collapses them). `MB.1.14`.
