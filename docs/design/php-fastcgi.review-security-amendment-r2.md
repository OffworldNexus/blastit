# Security review — `MB.3.9.2` amendment, round 2

**VERDICT: FAIL — 0 BLOCKER, 2 MAJOR, 11 MINOR.**
**Lens:** `security` (zero-trust, fail-closed, CVE resistance). DX/AI/testability are graded by their own lenses.
**Reviewed:** `docs/design/php-fastcgi.md` @ `sha256:6f0a11525783eff1249c2eb1e90ac5fe4581a2ae3ba04f1e27128857e828823d`; `docs/decisions/ADR-0008-fastcgi-backend-and-param-lockdown.md` @ `sha256:173cba78…cf17` (2026-11-14).

**Method:** verified the cited code facts (`crates/blastit/src/config.rs:1301-1321,1407-1411,674,677`; `stage0.rs:602-616`; `dev_learn.rs:106-117,149-204`; `sock.rs:452-454,497-519`) and then attacked as a `route_uid`-level compromise: app RCE, a `setsid()` escapee in the `S2`→`S6` window, a hostile leftover across an init restart, a second blastit instance, and the manifest/uid/path surfaces.

## 2. The six verification questions

**(1) `resolved_workers ≤ 64`, total?** Yes at the preflight. `R4` refuses `policy.resolved_workers(cap) > MAX_POOL_WORKERS` and an explicit `workers` outside `1..=64`; `check_fastcgi_workers(config.view_worker_cap())` runs in `stage0` production **and** `dev` (~`:1202`) and in `check::execute` before any runner branch. Omitted and explicit are both covered; `pm.max_children`, `RLIMIT_NPROC` and `RouteState.worker_cap` all read the one pure `resolved_workers(cap)`; `cap` comes only from `BLASTIT_VIEW_MAX_WORKERS`/`BLASTIT_MAX_WORKERS` (`config.rs:1407-1411,674,677,1301-1321`) — no route, uid or path input. Residuals: not structural at the consumers (`SEC-R2-4`) and the bound is per route (`N × 64` under `prefork`).

**(2) Mode chain = exactly the traversal `php-fpm` needs?** Yes, on the design's chain: `<runtime>` `0755` (`x` for the path walk, init-owned, never route-writable), `fastcgi` `init 0711` (`x` only; init the only writer, so no route can create/rename/list there), `<i>` `0700` at create → `0755 route_uid` for `S2`–`S6` → `init 0511` steady (`x` for `/proc/self/fd/<parentfd>/fpm.sock`, no `r`, no `w`). Across route uids, `0755` gives other routes `r-x` and no write, so `B` cannot plant in `A`'s `<i>`. Inside the bind window DAC cannot exclude the same uid — an accepted residual covered by `S4`/`S6`'s pgid check — but it is not "nothing in any phase". Exceptions: the ADR body still says `0555` (`SEC-R2-3`), and `dev`/`check` have no mechanism to skip the window (`SEC-R2-2`); `U1` now agrees (`0o511`).

**(3) Can `remove_entry` delete something that matters, or be turned against a foreign directory?** It cannot delete anything that matters: it only `unlinkat`s a name inside an init-owned `<i>`, and unlinking a hardlinked file leaves the data at its other name; `AT_REMOVEDIR` cannot cross a mount without `CAP_SYS_ADMIN`, which no route uid holds. It *can* fail into a whole-boot wedge (`SEC-R2-1`), and `B2`'s `EEXIST` normalisation can chown/chmod a foreign directory root placed at `<i>` (`SEC-R2-9`).

**(4) Two routes sharing a directory/pool/uid, and same-uid swaps?** No sharing: `<route_index>` is explicitly the index in `Manifest::routes`, "never the FastCGI-only ordinal" (`:225-229`, `fastcgi, wsgi, fastcgi` → `0`/`2`); uids are `UID_BASE+1000+i`; `B2` requires a distinct `(st_dev,st_ino)` per route; stage 1 rejects duplicate `(route, fd)` before any `OwnedFd`. Same-uid swap in production yields `Fault` `502`: `enforce_socket_inode = true` with `bound_inode` from `PoolReady`, `0600 scheduler_uid`, `SO_PEERCRED` `{route_uid:route_gid}` (`C1`). Residuals: the `None`-`bound_inode` skip (`SEC-R2-8`) and `dev`'s `false` (`SEC-R2-11`).

**(5) Any new path/host fact in success output, `--json`, `http_obs.jsonl`, `--learn`?** No. The new `dev` line is stderr and carries the route name, the resolved count and the budget variable's name only; the derived path appears only in boot diagnostics (`R3`) and `FastCgiPoolSocketInvalid`; `Config::to_json` excludes the `check_*`/obs fds. Only §1.2's prose contradicts the rule (`SEC-R2-10`).

**(6) Does `dev` being `Managed` weaken production?** No. `PoolSpawn` only selects whether `ensure_ready` calls `PoolPort::ensure_pool`; `B1`–`B3`/`S0`–`S7`/`U1`/`C1`, the `0711`/`0511` modes, `SO_PEERCRED` and `bound_inode` are production code paths driven by `stage0`/`Supervisor` and never read the mode. The reverse is true: `dev` inherits production's freeze without production's capabilities (`SEC-R2-2`).
