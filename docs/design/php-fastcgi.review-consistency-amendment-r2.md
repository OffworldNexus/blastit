## Answers to the four questions

**(a) `listen` — derived-socket prose is clean in the design, but the one refusal is not stated identically.**
No surviving design sentence treats `listen` as a key: every occurrence is the removal/unknown-key prose (`php-fastcgi.md:24-29`, `:194-195`, `:204-207`, `:368`, `:382`, `:629`), an INI directive of the generated pool file (`:294`, `:1302`, `:1348-1350`), the `listen(2)` syscall (`:1024`, `:1300`, `:1375`, `:1705`), or an explicitly historical alternative (`:1830-1839`, `:2165`, `:2166`). R1 (`:204-207`), §4.1's key table (`:382`), the variant table (`:406`), §7.2 (`:1875`, `listen_is_refused_by_name`) and §8.1 (`:2119-2120`, "the parser keeps the landed `FastCgiListenDerived` arm") all name `FastCgiListenDerived` with the message `route "app" (index 0): fastcgi listen: unknown key; the pool socket is created by blastit`, which is exactly what `crates/blastit-manifest/src/error.rs:511` prints and `parse.rs:958-960` emits. **But** §8's `MB.3.5.1` row says the opposite — "`listen` falls through to the existing `UnknownKey`" (`:1970`) — and the ADR says `ManifestError::UnknownKey` naming `route[<i>].fastcgi.listen` and "no 'removed key' hint is added" (`ADR-0008:288-290`). See F1.

**(b) `dev` pool — `Managed` in the forward-looking text, but a "never spawns" claim survives.**
§4.2.1 (`:720`), §4.8.1 (`:1274-1293`), §4.8.2's `dev` row (`:1307`), §7.2 (`:1883`, `dev_starts_one_pool_per_route` replaces the retired test), §8.2 (`:2167`), `docs/frameworks/php.md:33,58-66`, `MB.3.9.4/NODE.md:29` and the ADR (`:346-348`, "`PoolSpawn::Managed` is the only shipped mode (production, `dev`, and `check`'s child `dev`)") all agree. The retirement is recorded in **both** the design (`:1883`, "replaces the retired `external_pool_never_spawns_php_fpm`, which asserted the opposite of the amendment") and the ADR (`:344-348`). **However**, §9 still records the retired oracle as accepted and running under `dev` — `:2513` "after one request under `dev`, `/proc/<init_pid>/task/<init_pid>/children` has no pid whose `/proc/<pid>/comm` is `php-fpm`" and `:2525` "`external_pool_never_spawns_php_fpm` now states the `200` fake-peer precondition …" — with no superseded note. And §4.2.1:694 / §4.8.1:1271 keep the pre-amendment "the developer restarts `php-fpm` in place" premise. See F4, F9.

**(c) Two-phase probe / derived-parent variants / `MAX_POOL_WORKERS` / mode table — no, the mode table does not agree.**
Two-phase: R3 (`:241-245`), the trait (`:432-454`), §4.8.1 (`:1148-1180`), §4.8.3 (`:1403-1408`), §8.2 (`:2167`) and the ADR (`:349-350`) all say `parent` (phase 1, before the pool) then `check_leaf` (phase 2, after). `MAX_POOL_WORKERS = 64` is one value in R4 (`:247-254`), §4.1 (`:381`), §8 (`:1970`), §8.1 (`:2117`) and the ADR (`:305-308`). The derived-parent variants are one new `FastCgiPoolSocketInvalid` (dev/check) plus the stage-0 diagnostic (production). **The modes do not agree:** B3 (`:1365`) and S6 (`:1372`) freeze the parent `0o511`, the mode table says `0511` (`:1385`), R3 says `0511` (`:237`), §5.1 says `0511` (`:1723`) and §7.2's oracle restores `0511` (`:1884`) — but **U1 chmods `0o555`** (`:1374`) while its own invariant sentence says "succeeds in `0511`", and the **ADR says `0555`** for both the container and the child (`ADR-0008:196,220,223,282`) where the design says `0711`/`0511` (`:235`, `:1378-1385`). See F2. Three sentences also still assert `<runtime>` itself is `0700` (F3).

**(d) The ADR reads as a documented amendment — but one sentence inside `Amends` contradicts the design.**
It is not a silent edit: frontmatter `amended: MB.3.9.2` (`:5`), the dated blockquote (`:23-38`), dated §8.2 sync rows (`:2146-2169`) and an ADR `**Amends.**` section that quotes the retracted sentences by name (`ADR-0008:341-350`). The three "`dev`/`check` never spawn a pool" sentences survive in place but are explicitly retracted (`:49-50`, `:112-116`, `:237-239` → `:341-345`), which is an acceptable documented amendment. The exception: the `Amends` bullet's own `listen` paragraph says `UnknownKey` / `route[<i>].fastcgi.listen` / "no hint" (`:288-290`), contradicting R1/§4.1 and the shipped parser (F1). Separately, §9's "Round history (truthful state on disk)" (`:2175-2209`) does not record the amendment's own review round (F11).
