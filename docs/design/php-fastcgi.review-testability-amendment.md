# `php-fastcgi` amendment review — `testability` lens

- **Lens:** `testability` (verification and oracles)
- **Scope:** only the amendment dated **2026-11-14, labelled `MB.3.9.2`** — `docs/design/php-fastcgi.md` §1.2, §3 `R1`/`R3`/`R4`/`R20`, §4.1 (key table, error table, `SocketProbe`, probe-mapping tables), §4.8.1–§4.8.3, §7.1–§7.3, §8 (`MB.3.5.1`/`.2`, `MB.3.6.3.*`, `MB.3.7`), §8.1 item 4, §8.2 amended rows, and the `**Amends.**` bullets of `ADR-0008`.
- **Snapshot:** `docs/design/php-fastcgi.md` md5 `c0c37ca2a9e7c27c38ad0fffa78389ff` (2469 lines, current as of this review). The file was being edited while this review started; all line numbers below are that snapshot.
- **Enforcement model assumed:** named pure/unit tests (`critical_fastcgi_manifest.rs` at `MB.3.5.2`), one protected suite per behaviour, `e2e/rootless/run.py` for root-only legs, `#[ignore]`d `requires-root` elsewhere.
- **Accepted premises:** `listen` is gone; the socket is derived; `workers` is optional; over-budget is a boot error.

## VERDICT: **FAIL**

1 `BLOCKER`, 9 `MAJOR`, 6 `MINOR`.

The amendment's *own* headline rule (`listen` is an unknown key) is specified against an error variant and message that the enforcing crate does not produce: the parser on disk returns a dedicated `FastCgiListenDerived`, so the named test `listen_key_is_unknown` cannot pass. The rest of the new surface is mostly well-mapped (the derived-parent, pool-file and route-uid legs are named, and no fast-tier test needs `php-fpm` or root), but four rules the amendment introduces have **no oracle at all**: the `dev` resolved-workers line, `RLIMIT_NPROC`/`RLIMIT_NOFILE`, the over-budget *call sites*, and `capacity()` for omitted `workers`. Two assertions cannot be made unprivileged as written, and one owner brief still requires a test the amendment deleted.

## Failure modes worth restating

- **T1 is the amendment's own acceptance test.** The node brief says "the reviewer will read both" (`plan/nodes/MB/MB.3/MB.3.9/MB.3.9.2/NODE.md`), so the doc is the spec for a leaf that has already chosen a better message. Leaving the doc as-is forces one of three bad outcomes at `MB.3.5.2`: a failing protected test, a weakened assertion, or a second error variant for one rule.
- **T2/T3 are the same class the amendment was written to kill.** The design argues a clamp would make `pm.max_children`, `RLIMIT_NPROC` and `worker_cap` disagree. A missing call site makes them disagree just as badly, and nothing fails.
- **T7/T8 are the only genuinely new security checks in the amendment** (the pool parent and the pool leaf are blastit's now). Both currently have an oracle that is either privileged-only, partial, or contractually ambiguous.

## What holds

- No fast-tier named test needs `php-fpm` or root: the fake-`php-fpm` helper (`tests/support/fake_php_fpm.rs`, `MB.3.6.3.2`) and `PoolHarness`'s unprivileged subset are the right seams, and §7.1's "No Docker, no `php-fpm`, no pool in the unit gate" is honoured by the rows.
- Root-only assertions are correctly exiled (`fchownat`/`0555`/`0600` as `#[ignore] requires-root`; the multi-uid legs in `e2e/rootless/run.py`).
- Deleting `listen` genuinely removes requirements rather than hiding them: no rule in §4.1's table is left without an input, and `shared_listen_parent_is_boot_fatal` is gone from the design (T10 is the stale brief, not the design).
- The `R11` pool-file row has both twins for `pm.max_children` (omitted and explicit) and `§7.3` re-asserts `listen=`/`pm.max_children` through `php-fpm -tt` on the generated file, which is a good independent oracle.
