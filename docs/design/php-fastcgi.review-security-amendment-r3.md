# Security review — `MB.3.9.2` amendment, round 3 (focused re-check)

**VERDICT: FAIL — 0 BLOCKER, 2 MAJOR, 3 MINOR.**
**Lens:** `security` (zero-trust, fail-closed, CVE resistance). DX/AI/testability are graded by their own lenses.
**Reviewed:** `docs/design/php-fastcgi.md` @ `sha256:83a9ad77a96eafe15e637351a887015859e7fac933963785e2700a2299874f0e`; `docs/decisions/ADR-0008-fastcgi-backend-and-param-lockdown.md` @ `sha256:f79d0e7e9f5a0fa539ae9daa9a07f62d996e912e9efbe7a9c695af716bf0affd` (2026-11-14).
**Scope:** only the five re-check items requested after round 2 (`…review-security-amendment-r2.md`). Line anchors are for the hashes above.
**Method:** read the two documents, then attacked the new `remove_entry`, the dev/check sequence and the ADR modes as a `route_uid`-level compromise (app RCE, a `setsid()` escapee in the `S2`–`S6` window, a preserved `<runtime>`). Verified two code facts the design leans on: `crates/blastit-sys/src/caps.rs:86-95` (`CAP_DAC_OVERRIDE` is in `Capability::NEEDED`) and `crates/blastit-sys/src/privs.rs:54-101,418-438` (`drop_privileges` fails unprivileged at `setgroups`, asserted by the repo's own test).

## 1. Findings

| ID | Grade | Where | What | Fix |
|---|---|---|---|---|
| SEC-R3-1 | **MAJOR** | `php-fastcgi.md` §4.8.3 `remove_entry` paragraph (`:1421-1434`), `B3` (`:1390`), `S1` (`:1392`), `U1` (`:1399`) | **The rename-aside closes the first non-empty leaf and moves the wedge one name over; the "bounded" counter is itself attacker-trippable.** (a) During `S2`–`S6` `<i>` is `0755 route_uid`, so route code can create *any* name in `parentfd`. Five empty `mkdir fpm.stale.0…4` in one bind window trip `:1430-1431`'s "more than four `fpm.stale.*` entries is a boot error naming them" at the next `B3` → `exit 1` → **every route fails boot**, which is exactly the SEC-R2-1 class the paragraph claims to have removed ("a *cleaned* boot rather than a wedged one", `:1431-1434`). No guessing, no non-empty directory needed. (b) The destination is `fpm.stale.<master_pid>` (`:1427`). A same-uid escapee knows its own master pid (`getppid()`) and can plant a **non-empty** directory at that name in the same window; `renameat` then returns `ENOTEMPTY`, and "Anything else is an error" (`:1429`) becomes a boot error. At `B3`/`S1` no new master exists yet, so `<master_pid>` is undefined — a cheap implementer will use `getpid()` (init's, fixed and observable) or the previous master's pid (known to the escapee), which makes the collision deterministic rather than racy. (c) `U1`'s "Leaves **nothing usable** … holding no non-socket entry" (`:1399`) is false once the rename succeeds: a linked `fpm.stale.<pid>` tree survives, no code path ever reclaims it, and `/run` is tmpfs, so the escapee can park unbounded child data there. (d) The paragraph only defines a **boot** failure; it says nothing about `remove_entry` failing at `S1`/`U1` during `spawn_pool`, where "boot error" can only mean init exiting and taking every route with it. *Not an integrity bug:* the rename stays inside `parentfd`, never follows a symlink, and the only names that matter are `fpm.sock`/`fpm.stale.*`, so replacing a planted file/empty directory at the destination is harmless. **Mode precision:** `0511` gives the *owner* no `w`, and `B3` freezes **before** cleaning (`:1390`), so every `B3`/`S1`/`U1` removal works only through `CAP_DAC_OVERRIDE` — which `Capability::NEEDED` does require (verified), but `U1`'s "because init is the owner and also holds `CAP_DAC_OVERRIDE`" (`:1399`) is wrong about the owner half, and `B3`'s capability error names only `CAP_CHOWN`/`CAP_FOWNER`. | Never convert a leftover into a whole-boot error: any `fpm.stale`/removal fault marks **only that route** `Busy` (`503` + named diagnostic) and boot continues, matching `R20`'s per-route 503 shape. Reclaim at boot with a bounded walk (`openat(name, O_DIRECTORY\|O_NOFOLLOW\|O_CLOEXEC)`, `unlinkat`/`rmdir`, depth ≤ 4 / entries ≤ 64) instead of counting entries. If rename-aside is kept, use `renameat2(…, RENAME_NOREPLACE)` over a fixed, bounded suffix set that is **not** a route-predictable pid (or `fpm.stale.<monotonic counter>`), loop on `EEXIST`/`ENOTEMPTY`, and specify `S1`/`U1` behaviour. Tests: `five_planted_stale_entries_do_not_stop_boot`, `planted_stale_destination_cannot_wedge_rename`, `unwind_failure_leaves_only_that_route_503`. |
| SEC-R3-2 | **MAJOR** | `php-fastcgi.md` §4.8.3 single-uid variant (`:1412-1419`), `U1` (`:1399`), `S0` (`:1391`)/`S3` (`:1394`), §4.8.2 Command row (`:1325`) | **The skip list names `S2`/`S5`/`S6`, but two production-only actions live inside the *kept* steps, so the variant cannot run as written — and the obvious repair weakens production.** (a) `U1` is kept, and `U1`'s first action is "**then freeze first** — `fchownat(parentfd, c\"\", init_uid, init_gid, AT_EMPTY_PATH)` + `fchmodat(parentfd, c\".\", 0o511, 0)`". In `dev`/`check` `init_uid` is the invoking uid, so that chown/chmod is permitted and really does set `0511`; `remove_entry` then has no `w` and no `CAP_DAC_OVERRIDE` (the harness holds none) → `EACCES`, and even a successful unlink leaves a `0511` directory that fails `DevProbe::parent`'s exact-`0700` predicate on the next `dev` over the same root — the design says so itself at `:1417-1418`. The paragraph's "nothing is frozen" is intent; the sequence it lists still freezes. (b) `S0` and `S3` are kept and their child runs "`drop_privileges(route_uid)` … exactly S3's sequence" (`:1325`, `:1391`, `:1394`). `drop_privileges` is **not** a no-op when `uid == euid`: it calls `setgroups(0, NULL)` first, which needs `CAP_SETGID`; `crates/blastit-sys/src/privs.rs:418-438` asserts that exact failure for an unprivileged caller. So the documented `dev`/`check` pool and its `php-fpm -t` child fail closed at boot. The natural local fix — making `drop_privileges` tolerant of `EPERM` — would silently weaken the production `execve` barrier. The *intent* is sound and no production invariant is weakened by the modes themselves (`0711`/`0511`/`S2`/`S5`/`S6` are explicitly production-only, `DevProbe`'s predicate is `0700`, `ProductionProbe` never enters it); the sentence is not yet the mechanism. | Pin the whole variant, not just three skipped steps: a `freeze: bool` (false when `init_uid == route_uid`) so `U1`'s `fchownat`/`fchmodat` are skipped too; and `if euid() != uid { drop_privileges(uid)? }` in the shared pool / `-t` child (never a tolerant `drop_privileges`). Pin the variant selector explicitly (`init_uid == route_uid`, derived from the `UidLayout`, not from `PoolSpawn`) and make a production layout with equal uids a boot error. Tests: `critical_fastcgi_dev_pool::{dev_pool_retire_leaves_parent_0700_invoking_uid, dev_pool_child_keeps_invoking_uid}` and `critical_fastcgi_pool::production_pool_child_still_drops_to_route_uid`. |
| SEC-R3-3 | MINOR | `ADR-0008:192,196,220,225,226,228` vs its own `Amends` bullet `:285-293` and `:343-353` | **SEC-R2-3 is still open: decision 6's body says `0555` in six places while the design and the Amends bullet say `0700 → 0755 route_uid → 0511`.** Lines 192 ("creating only an absent final leaf `0555`"), 196 ("freezes `parentfd` `init_uid:init_gid 0555`"), 220 ("restore owner and mode `init_uid:init_gid 0555`"), 225-228 (U1 "freeze first … `0555`", "cannot write `0555`") contradict `:290-292` (`0511` steady) and the design's `B2` (`0o700`) / `B3` (`0o511`). The decisions-1-and-6 bullet then calls "the freeze/bind window … unchanged" (`:352-353`) without retracting them, so a leaf citing "decision 6" ships a world-listable `<i>` (and `0555` also denies the owner `w`, making the unlink capability-only). | Rewrite the six `0555` occurrences to `0511` (and the "absent final leaf `0555`" to `0700`), keep `CAP_DAC_OVERRIDE` only as the production-unlink justification, and add `! grep -n 0555 ADR-0008 …` to `MB.3.8`'s acceptance. |
| SEC-R3-4 | MINOR | `PoolConf` doc (`:1349-1351`: "one derivation site, `R3`"), `render_pool_conf` (`:1327`), `check_fastcgi_leaf` (`:521-522`), `DevProbe::parent` (`:1184-1191`), `B2` (`:1389`) | **"One derivation site" is inaccurate; only the *formatter* is single.** The suffix `fastcgi/<i>/fpm.sock` is spelled independently in `DevProbe::parent` (`mkdirat` + `openat2`), `check_fastcgi_leaf` (message path), `render_pool_conf` (`listen=`), and `B2` (`mkdirat`/`openat2`). ## 3. Acceptance condition

Zero MAJOR to pass. SEC-R3-1 needs the route-scoped degradation (no whole-boot `exit 1` from a leftover, bounded reclaim, collision-proof rename) and its three tests; SEC-R3-2 needs the variant to name *every* production-only action it skips (`U1` freeze; `drop_privileges` when `euid == uid`) plus the selector and its two/one tests. The MINORs are one-line/small changes: SEC-R3-3 belongs with `MB.3.8` (ADR text), SEC-R3-4 with `MB.3.5.2` (the `R3` helper), SEC-R3-5 with `MB.3.6.3.2` (the renderer).
