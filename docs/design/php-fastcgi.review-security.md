### 1.1 The specific claims, checked

- **`init` keeps one `Arc<OwnedFd>` per route while `S1`–`S7`/`U1` run on it:** yes, §4.8.1:814-821; all eight steps name `init` as caller (`S1`:896 … `U1`:903); only `http`/`dbproxy`/`view`/`pool` drop their copies.
- **Stage 1 validates the fd list before wrapping:** yes, §4.8.1:802-809, including unique route/fd, `fd >= 3`, not `config_fd`/dbproxy fd, `S_ISDIR`, and "no descriptor wrapped" on a violation.
- **`S1` reaps the prior pgid to `ECHILD` before `S2`:** yes, `S1`:896 ("`waitpid(-old_pgid, WNOHANG)` until `ECHILD` (bounded 100 ms; not `ECHILD` → **Unwind U1**, the window never opens)") precedes `S2`:897.
- **`S4`/`S6` membership rule sound:** yes for the stated threat model. `S4`:899 records only a socket held by a task whose `/proc/<pid>/stat` `pgrp == master_pid`; `S6`:901 re-runs it after the freeze. An escapee's rebind is not held by a new-pgid task, so it is never recorded. The residual is same-uid `SCM_RIGHTS` into a cooperating new-pgid task (MINOR-40), not a cross-route path.
- **`U1` freezes before `unlinkat`:** yes, `U1`:903 ("**then freeze first** ... **then** `unlinkat`"), with `CAP_DAC_OVERRIDE` for the `0555` unlink.
- **§7.2 oracle fails on an escapee rebind:** yes, §7.2:1294: the fake pool records its bound inode; the test asserts `PoolReady.sock_ino` **equals** that inode; an escapee rebind yields **no** `PoolReady`, `U1`, `Busy` → `503` + `Retry-After: 1`, and `0` `accept`s.
- **`SO_PEERCRED` sets exact per mode:** yes, §4.5.2:658 and `C1`:904: production `{route_uid:route_gid}`, `dev`/`check` `{invoking_uid:invoking_gid}`, `scheduler_uid` rejected, no gVisor tolerance.
- **Single handoff source, config document excluded:** yes, §4.8.1:785-850 (argv `--fastcgi-parent-fd` only; negative rule at 847-850), §4.8.1:835-841 (neither `check_pool_parent_fds` nor `check_sql_obs_fd` is in `to_json`), ADR:113-122,174-175.

## 3. New findings (MINOR only)

**MINOR-38 — `set_dumpable(false)` before `execve` does not survive the exec.**
§4.8.2 Command:869 lists `set_dumpable(false)` and `S3`:898 runs it before `execve php-fpm -F -y`. The kernel's `begin_new_exec` sets `dumpable = SUID_DUMP_USER` for a non-setuid, non-file-cap binary (`fs/exec.c`: the `BINPRM_FLAGS_ENFORCE_NONDUMP` / `euid != uid` branch is false), so the master is dumpable after exec. This does not break `S4` — init has `CAP_DAC_OVERRIDE` (`caps.rs` `NEEDED`) and `/proc/<pid>/fd` is owned by `route_uid` mode 0500, so the membership scan still reads it — but the design's "set_dumpable(false)" is not the isolation control it reads as. The sanitized env (no `BLASTIT_*`, no `HTTP_PROXY`) is the actual `/proc/<pid>/environ` control. *Fix:* drop the claim, or state "the master is dumpable after `execve`; its environment is the sanitized map, and `/proc/<pid>/fd` is read by init via `CAP_DAC_OVERRIDE`". If `php-fpm` ever carries file capabilities/setuid, `secureexec` would set dumpable to `suid_dumpable` (0) and `S4` would fail `EPERM` for a non-root init — state the assumption.

**MINOR-39 — the pool conf is writable by `route_uid`, and `open_basedir` does not stop an `exec`'d helper.**
§4.8.2 Pool file:871: "`<runtime>/views/<uid>/php-fpm.conf`, `0600` route uid ... the private dir itself is deliberately **not** added to `open_basedir`, so the app can neither read nor rewrite its own `php-fpm.conf`". `open_basedir` is a PHP-level restriction; a `shell_exec`/`proc_open` helper or a surviving `setsid()` escapee (same `route_uid`) can read/write the `0600 route_uid` file. `S0`:895 renders it and `S3`:898 execs `php-fpm -F -y <path>`; an escapee can rewrite it between `S0` and `S3`, weakening the INI backstops (`allow_url_include`, `auto_prepend_file`, `user_ini.filename`, `open_basedir`, `cgi.fix_pathinfo`, `security.limit_extensions`) for the next generation. The param wall still holds, so this is defence-in-depth, not a `php2shell` path. *Fix:* render the conf `0400 init_uid` and pass it by fd (`php-fpm -y /proc/self/fd/<conf_fd>` with the fd inherited — the Round-5 MAJOR-C option-2 pattern), or state the residual honestly.

**MINOR-40 — the S4/S6 residual names `ptrace`, which is seccomp-denied.**
§4.8.2:869: "Residual after that: an escapee that can inject an fd into, or `ptrace`, a new-pgid task (same-uid, beyond this model)". `seccomp.rs` `DENIED` (`:210-246`) refuses `ptrace`, `pidfd_getfd`, `kcmp`, `process_vm_readv`, `process_vm_writev` for **every** role, and the pool is `SeccompRole::View { egress }`, so those calls are `EPERM`. The practical same-uid injection is `SCM_RIGHTS` over an `AF_UNIX` socket to a cooperating new-pgid task (the app's own code). *Fix:* name `SCM_RIGHTS` and drop `ptrace` (or say "seccomp-denied except `SCM_RIGHTS`"), so the residual is the one that is actually reachable.

**MINOR-41 — `U1`'s `kill(-pgid)` can signal a reused pgid.**
`U1`:903: "If forked: `kill(-pgid, SIGKILL)` + reap". If `S3`'s `waitpid(pid, WNOHANG)` (`:898`) has already reaped the master, `pgid` is free for reuse; `kill(-pgid)` can signal an unrelated process group (init has `CAP_KILL`). The window is small, but the consequence is a cross-route kill. *Fix:* open `pidfd_open(master_pid)` at fork time and signal through `pidfd_send_signal` (init installs no seccomp filter), or kill before reaping, and guard `pgid > 1`.

**MINOR-42 — `S0` has no timeout.**
`S0`:895 forks `php-fpm -t -y <conf>` and waits; `S3`:898 has a 5 s non-blocking poll, `S0` does not. A hung `php-fpm -t` (malformed conf, a stuck path, a `php-fpm` bug) blocks init's boot/pre-spawn path. *Fix:* bound `S0` like `S3` (5 s → boot error/`U1`) and drain/cap its stdout/stderr.

**MINOR-43 — `parent_dev`/`parent_ino` provenance is unstated.**
`S1`:896: "`fstat(parentfd)` asserts `(st_dev, st_ino) == (parent_dev, parent_ino)`"; `C1`:904: "`fstat(parent)` == `(parent_dev, parent_ino)`". If `parent_dev`/`parent_ino` are recorded from `fstat(parentfd)` (as `PinnedSocket` suggests), the equality is tautological. If they are recorded from `fstatat(manifest_dirfd, rel_parent)` at `B2`/`B3`, the check detects a swap. *Fix:* state the provenance (path `fstatat`) or delete the check.
