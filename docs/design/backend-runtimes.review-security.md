# Security review — `docs/design/backend-runtimes.md` (MB.12), round 7

**Lens:** `security`
**Reviewed:** `docs/design/backend-runtimes.md`, `docs/decisions/ADR-0009-runtime-providers-and-capability-gating.md`, `docs/decisions/ADR-0010-php-embedded-via-libphp-embed.md`, `docs/design/backend-runtimes.resolve-owner.md`, `docs/VISION.md`, `ARCHITECTURE.md` §7.3/§8, `docs/security.md`, `docs/research/php-embed-sapi.md`, `docs/research/php2shell.md`, `crates/blastit/src/supervise.rs`, `crates/blastit-sys/src/{seccomp,signal,privs}.rs`, `crates/blastit-dbproxy/src/role.rs`.
**Verdict:** **FAIL** — 0 `BLOCKER`, 2 `MAJOR`, 15 `MINOR`.

The six round-6 `MAJOR`s are closed in substance: reverse-accept `HttpUpstream`, `SCM_RIGHTS` rejection on every channel, the full forwarded-header family, gVisor-safe `waitid(P_PID, WNOWAIT)` leader pinning, and `rlimit_nproc` under `hidepid=2` are all specified and testable. Two `MAJOR`s remain: the PHP CPU floor is leader-only while `EmbeddedView` permits threads (measured below), and `ADR-0010` still pins `include_path=.` with no `cwd`, contradicting the design's absolute `include_path=<manifest_dir>`.

---

## MAJORs

### M1 — PHP's `max_threads = 1` + leader-only `/proc/<pid>/schedstat` is undercharged whenever a PHP thread exists, and `EmbeddedView` explicitly allows `clone(CLONE_THREAD)`

**Quotes:** R19 (§2, line 62): “`max_threads` is `1` for NTS PHP (`EmbeddedView` forbids `fork`) and live `/proc/<pid>/status` `Threads:` … for multi-threaded `View` workers (**WSGI, Node, JVM**)” and “`kernel_floor_ns` reads `/proc/<pid>/schedstat` for PHP and **`max(sum(pgrp_tasks_schedstat), /proc/<pid>/stat utime+stime+cutime+cstime)`** for `View` workers”. R14 (line 57): “`EmbeddedView` additionally returns `EPERM` on `execve`, `execveat`, `fork`, `vfork`, and `clone` without `CLONE_THREAD` (`(args[0] & CLONE_THREAD) == 0`)” — i.e. `clone(CLONE_THREAD)` is **allowed**. §6 rejected alternative #5 (line 283): “Clamp worker CPU below by `dispatch -> first_frame` or leader-only `schedstat`” is rejected because “Compromised worker … burns CPU on a non-leader pool thread, reports `0`, and starves honest flows”.

**Failure mode:** `/proc/<pid>/schedstat` is the **thread-group leader's** `se.sum_exec_runtime`, not the process sum. Measured on this host with a process whose non-leader thread burned ~1.2 s: `/proc/self/schedstat` field 1 = **33.9 ms** while `/proc/self/stat` `utime+stime` = **1.23 s** (ratio 0.03). With `max_threads = 1`, `ceiling = observed_wall_ns × 1`, and `reported_cpu_ns` (process-wide `CLOCK_PROCESS_CPUTIME_ID`, which *does* include threads) is clamped down to `ceiling`. A PHP worker that creates a thread — any loaded extension that calls `pthread_create` (`swoole`, `parallel`, `grpc`, …), which `EmbeddedView` does not block — burns N×wall and is charged at most 1×wall. That is precisely the starvation attack alternative #5 says the design closes, and no `critical_fair_cpu.rs` case covers a threaded PHP worker (the “multi-threaded worker … charged `>= 2 s`” oracle is a `View` worker).

**Suggestion:** use the same bound for PHP as for `View`: `max_threads = live /proc/<pid>/status Threads:` (clamped `1..=rlimit_nproc`) and `kernel_floor_ns = max(/proc/<pid>/schedstat, /proc/<pid>/stat utime+stime)`; or deny `clone` entirely on `EmbeddedView` and document that threaded extensions are unsupported. Add a `critical_fair_cpu.rs` case: a PHP worker with two threads burning 2×wall is charged `>= 2×wall` (or the filter returns `EPERM` on the thread clone).

### M2 — `ADR-0010` still pins `include_path=.` and omits `cwd`, contradicting the design's absolute `include_path=<manifest_dir>`

**Quotes:** `ADR-0010` §2 (line 25): “`ZEND_INI_SYSTEM` lock … `include_path=.`, `sendmail_path=`, …”. Design R12 (line 55): “PHP worker sets `cwd = manifest_dir` (read-only) with absolute `include_path=<manifest_dir>` (`m7-R6`)”. Design §5.1.3 (line 255): “`blastit-php-sapi` sets `cwd = manifest_dir` (read-only) with absolute `include_path=<manifest_dir>` (`m7-R6`) … `include_path=<manifest_dir>`”. Design `(M-6)` (line 239): “absolute `include_path=<manifest_dir>`”.

**Failure mode:** `ADR-0010` is the decision record `MB.3.12` implements, and it (a) never sets `cwd` and (b) sets a relative `include_path`. `chdir()` is not in `disable_functions`, and `open_basedir=<manifest_dir>:<view_tmp>` permits `<view_tmp>`. An app that `chdir`s to its upload directory and then `include`s a relative path resolves `.` to `<view_tmp>` and executes an attacker-written file — the LFI→RCE chain `m7-R6` exists to close. The `critical_php_abi.rs` assertion “`cwd == manifest_dir` & `include_path == manifest_dir`” (line 297) is the backstop, but an implementer reading the ADR writes the vulnerable value and only learns at test time.

**Suggestion:** change `ADR-0010` §2 to “`cwd = manifest_dir` (read-only) with absolute `include_path=<manifest_dir>`; `php_ini_ignore_cwd = 1`”, and add the `post_max_size`/`upload_max_filesize`/`max_input_vars` entries §5.1.3 already pins.

## MINORs

- **m1 — §9 still contains the rejected `hidepid=2` cap.** §9 line 342: “capped `hidepid=2` fallback multiplier to `route_allocation.min(4)` (`cpu_source: "ceiling"`)” contradicts R19, §4.5, `ADR-0009` Decision 4, `ADR-0010` `(M-4)` and §9 line 344 (“raised `hidepid=2` `View` fallback ceiling to `rlimit_nproc`”). Delete the sentence; it is the residue of the round-6 M6 fix.
- **m2 — §9's `CLONE_NEW*` mask and `EmbeddedView` summary are stale.** §9 line 341 writes `clone(args[0] & 0x7E020000 != 0)` (missing `CLONE_NEWTIME` `0x80`; R14/§5.1.3 use `0x7E020080`) and summarises `EmbeddedView` as “plus `execve`/`execveat -> EPERM`”, omitting `fork`/`vfork`/non-`CLONE_THREAD` `clone` that R14 and `ADR-0009` require. Align the text.
- **m3 — the `waitid(WNOWAIT)` peek is not ordered against the generic reaper.** `crates/blastit-sys/src/signal.rs:243` is `waitpid(-1, …, WNOHANG)`, which will reap a registered leader before any `waitid(P_PID, …, WNOWAIT)` peek unless the peek → `getpgid` check → `kill(-pid)` → `waitpid(pid)` sequence runs first. R5 says “keeping the zombie leader un-reaped until … complete” but never states that ordering, and `MB.3.19`'s paths (§8.2 row 6) omit `crates/blastit-sys/src/signal.rs`. Pin the order and add the path (or a `reap_except(leader)` helper).
- **m4 — the `accept.sock` Stage-0→Stage-1 fd handoff is unspecified.** R23/§4.2 say “`scheduler`-inherited `UnixListener`”, but `scheduler` is forked from Stage 1 *after* the Stage-0→Stage-1 `execve`. State that the listener is non-`CLOEXEC` across that `execve`, re-marked, passed via `ChildIo.keep`, and closed in `http`/`dbproxy`/workers; add it to `MB.3.19`/`MB.9.3` paths and the `critical_http_upstream_smuggling.rs` oracle. Otherwise M1's fix silently regresses.
- **m5 — `PR_SET_DUMPABLE(0)` is reset by `setresuid` and never re-applied to view/probe children.** `drop_privileges` (`crates/blastit-sys/src/privs.rs:1-50`) calls `setresuid`, which sets the dumpable attribute back to 1; `harden_child` (`privs.rs:217`) sets only `PDEATHSIG` + `NO_NEW_PRIVS`, and §5.2's child-setup row omits dumpable. `crates/blastit-dbproxy/src/role.rs:50` already re-applies `set_dumpable(false)` — pin the same for view/probe children (defence in depth; `RLIMIT_CORE=0` and the `ptrace` denial remain the mechanisms). `ADR-0010` §1.1 also still omits `PR_SET_DUMPABLE(0)` (the `m13-R6` sync landed only in `ADR-0009`).
- **m6 — “`capget`-verified empty capability sets” is not what `capget` can prove.** R5 (line 48) and the test plan (line 293) say `capget`; `capget` reports permitted/inheritable/effective only. Ambient is cleared by `PR_CAP_AMBIENT_CLEAR_ALL` and bounding by `PR_CAPBSET_DROP`; the existing `drop_privileges` reads `/proc/self/status` and does both. Say “verified via `/proc/self/status` + ambient/bounding drop” so the oracle matches the mechanism.
- **m7 — `ALWAYS_STRIP` omits the OpenSSL loader family.** R12/§5.1.3 list `LD_PRELOAD`/`GCONV_PATH`/`NODE_*`/`JAVA_*` but not `OPENSSL_CONF`, `OPENSSL_ENGINES`, `OPENSSL_MODULES`, `SSLKEYLOGFILE` (nor `PERL5OPT`/`RUBYOPT` if those runtimes are ever hosted). An operator/PaaS env var can make a Node/Python/PHP process `dlopen` an attacker engine or log TLS session keys. Add them to `const ALWAYS_STRIP`.
- **m8 — `bt_getenv`'s sanitized table is unspecified.** §5.1.3 says “serves `sapi_module.getenv` (`bt_getenv`) exclusively from its sanitized table” but never says what is in it. State that it is empty (or a fixed `PATH`/`TZ`-only set) so a cheap implementer cannot pass the worker's `environ` through.
- **m9 — `X-Forwarded-For`/`-Proto` are only as trustworthy as `BLASTIT_TRUSTED_PROXIES`.** §4.2/M3-R6 say they are written “solely from `head.remote_addr`/`head.scheme`”, but both presets use `*` (`docs/security.md` line 125: “Both presets use `*`: every peer is trusted”), so a direct client's `X-Forwarded-For` becomes `head.remote_addr` and is re-emitted to Node/Tomcat frameworks that trust it. State the dependency in §4.2 and add a preset test.
- **m10 — stale `fd 3` references contradict the reverse-accept contract.** §4.3 `ProviderKind::Managed` comment (line 154) “MB.4 Node (fd 3) | MB.5 JVM (pools/<slot>/http.sock)” and `resolve-owner.md` line 11 “per-route `node` worker on inherited `fd 3`” contradict §4.2, R23, §3.1 and §4.6. `fd 3` is the exact seam round-6 M1 rejected; delete both.
- **m11 — `docs/VISION.md` still names PHP-FPM/FastCGI.** Lines 33 (“PHP (PHP-FPM / FastCGI)”) and 47 (“**PHP-FPM** (FastCGI wire protocol …)”) contradict the sole-embedded-`libphp` decision. §8.1 assigns this to `MB.3.8`, but `MB.12` owns `docs/**` and can fix it now.
- **m12 — the cited research note contradicts R8/R13.** `docs/research/php-embed-sapi.md` §2 line 54 still says the probe `dlopen`s at “Stage-0 preflight”, and §3 line 60 recommends a per-route zygote sharing OPcache SHM — both contradict R8 (post-barrier probe, zero Stage-0 `dlopen`) and R13/§6 #6 (zero shared writable SHM). Add a one-line correction so `MB.3.12` implementers do not follow R§2/R§3.
- **m13 — the `HttpUpstream` test plan omits half the forwarded family it strips.** Line 300 lists `Forwarded`/`X-Forwarded-Host`/`X-Real-IP`/`X-Original-URL`/`X-Rewrite-URL` but not `Client-IP`, `True-Client-IP`, `X-Forwarded-Port`, `X-Forwarded-Prefix`, `X-Forwarded-Server`, all stripped in §4.2. Add them.
- **m14 — `HttpUpstream` response chunk/trailer bounds are unspecified.** §4.2 rejects `CL`+`TE`, duplicate `CL`, obs-fold, non-`tchar`, CTL and the four proxy-control headers, but never bounds chunk size, trailer count or trailer headers. State that trailers are dropped and chunks are bounded by `BLASTIT_REQUEST_TIMEOUT` + `blastit-http`/`ResponseSink` limits.
- **m15 — `MB.3.19` is still “proposed”** (§8.2 row 6, line 330) although it is the release-blocking owner of `EmbeddedView` seccomp, `PR_SET_CHILD_SUBREAPER(1)` and the `setpgid`/`getpgid` guard. `lead` must create it before `MB.3.8`; until then the `0.2.1` release gate has no node on disk.

## Verified positives

- **Reverse-accept `HttpUpstream` (round-6 M1/M2/M3 closed):** R23/§4.2 — `accept4(SOCK_CLOEXEC)` on a `scheduler`-inherited `AF_UNIX` `UnixListener` (`0700`/`0600` `route_uid`, `SO_PASSCRED` unset), worker `connect()`s one `Connection: close` exchange per stream, zero `socket()` in `scheduler` (`ARCHITECTURE.md` §7.3: “http, scheduler: no `socket()` at all”; `seccomp.rs` `sockets()` is `false` for `Http`/`Scheduler`). `HttpUpstream` reads with plain `read`/`recv` (zero `msg_control`), `dbproxy` closes `SCM_RIGHTS` with `MSG_CMSG_CLOEXEC`. Full family stripped (`Forwarded`, `X-Forwarded-For/Proto/Host/Port/Prefix/Server`, `X-Real-IP`, `X-Original-URL`, `X-Rewrite-URL`, `Client-IP`, `True-Client-IP`), `XFF`/`XFP` rewritten from `head.remote_addr`/`head.scheme`; strict response parsing rejects `1xx`/`101`, `CL`+`TE`, duplicate `CL`, obs-fold, non-`tchar`, CTL, `X-Accel-Redirect`/`X-Sendfile`/`X-Lighttpd-Send-File`/`X-Rewrite-URL`, and suppresses `HEAD` bodies.
- **gVisor-safe reaping (round-6 M4/M5 closed):** single-threaded `init` with `SIGCHLD` in a synchronous `SignalFd` (`signal.rs:145` `signalfd(SFD_CLOEXEC|SFD_NONBLOCK)`; `supervise.rs:10` is a signalfd loop), `PR_SET_CHILD_SUBREAPER(1)`, `waitid(P_PID, WEXITED|WNOHANG|WNOWAIT)` leader peek (`pidfd_open` optional bonus), `getpgid(pid) == pid && pid != getpgid(0)` before `kill(-pid, SIGKILL)`, pre-filter `setpgid(0,0)`. `drop_privileges` clears ambient/inheritable/bounding before the uid change and permitted/effective after, verified via `/proc/self/status`; `harden_child` sets `PR_SET_NO_NEW_PRIVS`.
- **`hidepid=2` fallback (round-6 M6 closed in the requirement):** R19/§4.5/`ADR-0009`/`ADR-0010` all say `rlimit_nproc` in `Production` and `max_workers` in `Dev`, `bounded = reported.min(ceiling).max(kernel_floor_ns)`, wire `wall_ns` ignored, 9/17-byte `RESP_END_COST` accepted once before `DONE`.
- **Sole embedded PHP backend:** `ADR-0010` §1.1/§2 — NTS `libphp` over `view.chan`, no FastCGI/`php-fpm`/`[route.fastcgi]`; `MB.3.17` deletes `crates/blastit-fastcgi`, `stage0.rs:362`, `no_python_build.rs:153`, `BLASTIT_ALLOW_EXTERNAL_FASTCGI`; `critical_no_fastcgi` asserts `cargo metadata` has no `blastit-fastcgi`.
- **`blastit_php_abi_v1`:** `abi`/`size`/`zend_api`/`php_minor` checks, `zend_first_try`/`zend_catch` inside C, `catch_unwind` on Rust callbacks, fd-pinned `dlopen("/proc/self/fd/<N>", RTLD_NOW|RTLD_LOCAL)`, `RTLD_DEEPBIND` rejected, post-fork `php_module_startup` (zero shared writable SHM).
- **PHP lockdown:** `php_ini_ignore_cwd=1`, isolated `bt_getenv`, `PATH_TRANSLATED` omitted, `dl()` omitted, `HTTP_PROXY` omitted from `$_SERVER`, `variables_order=GPCS` (no `E`), `allow_url_include=0`, `allow_url_fopen=0` (`!egress`), `auto_prepend_file=`/`auto_append_file=`, `user_ini.filename=`, `ffi.enable=0`, `phar.readonly=1`/`phar.require_hash=1`, `opcache.preload=`/`file_cache=`/`jit=0`, `memory_limit=256M`, `open_basedir`, `disable_functions` incl. `putenv`/`posix_kill`/`pcntl_*`, `zend.assertions=-1`, `EntryScript` `.php`/`.phar` `404`.
- **`EmbeddedView` seccomp:** `clone3 -> ENOSYS`, `clone(0x7E020080) -> EPERM` (all `CLONE_NEW*` incl. `CLONE_NEWTIME`), `setsid`/`setpgid -> EPERM`, `execve`/`execveat`/`fork`/`vfork`/non-`CLONE_THREAD` `clone -> EPERM`, 35 shared `DENIED`, `MAX_PROGRAM 96` (current worst case 54, `seccomp.rs:280`).
- **Stage 0:** `RLIMIT_CORE=0` + `PR_SET_DUMPABLE(0)` before any secret; `Zeroizing` buffers dropped before `execve`; `plain_is_protected` + `!has_file_caps` + `DT_RPATH`/`DT_RUNPATH` rejection + pre-scanned `.ini`/`extension_dir`/`extension=`/`zend_extension=` + `(st_dev, st_ino)` pin + `/proc/self/fd/<N>` load; read-only `manifest_dir`/`entry`/`static.root`; post-barrier `-pgid` probe with `env = {}` and `--role=php-probe` rejected in `Production`.
- **`const ALWAYS_STRIP` + `BLASTIT_*`:** non-configurable, applied after user `BLASTIT_ENV_STRIP`; `LD_PRELOAD`/`LD_AUDIT`/`GLIBC_TUNABLES`/`GCONV_PATH`/`PYTHONHOME`/`CLASSPATH`/`PHPRC`/`PHP_INI_SCAN_DIR`/`PHP_VALUE`/`PHP_ADMIN_VALUE`/proxy/`NODE_*`/`JAVA_*`; `LD_LIBRARY_PATH` stripped in `Production`, wheel `dev`/`check`, and all PHP/Node/JVM workers.
- **`musl` drop-not-degrade `(M-1)`–`(M-6)`** with Alpine `php2shell`/`phar://` e2e and the “4 proven on 8.4 until 8.2/8.3 built+probed” provenance rule.

## Test-plan gaps

- `critical_fair_cpu.rs`: threaded PHP worker (M1) — two threads burning 2×wall charged `>= 2×wall`, or `clone(CLONE_THREAD)` denied.
- `critical_php_abi.rs`: assert `cwd == manifest_dir` **and** `ini_get('include_path') == manifest_dir` from the ADR-0010 text as written (M2).
- `critical_provider_parity.rs`: registered leader exiting immediately must not be reaped by `waitpid(-1)` before the `WNOWAIT` peek (m3); `accept.sock` survives the Stage-0→Stage-1 `execve` and is absent in `http`/`dbproxy`/workers (m4); `dumpable() == false` in view/probe children (m5).
- `critical_http_upstream_smuggling.rs`: `Client-IP`/`True-Client-IP`/`X-Forwarded-Port`/`-Prefix`/`-Server` (m13); unbounded chunk/trailer response (m14); `X-Forwarded-For` spoof under a `*` trusted-proxy preset (m9).
- `critical_php_embed.rs`: `bt_getenv` returns nothing for `LD_PRELOAD`/`HTTPS_PROXY`/`BLASTIT_*` even when set in the parent (m8); `OPENSSL_CONF`/`OPENSSL_ENGINES` stripped (m7).

---

## Overall verdict

**FAIL.** The architecture is sound and the round-6 closures are real, but M1 (PHP CPU floor is leader-only while `EmbeddedView` allows threads — measured 0.03× undercount) and M2 (`ADR-0010` still pins `include_path=.` with no `cwd`) are security-relevant defects in the sole PHP backend, not polish. Both are one-line fixes; re-run this lens after they land.
