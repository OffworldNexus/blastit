## 1. Five Settled Architectural Principles

Blastit started as a Python WSGI server (`0.1.1`) where `init` embedded CPython, froze the heap, and forked per-route `view` children from its own binary. Serving Static (`0.2.0`), PHP (`0.2.1`), Node/Vite SSR (`0.2.2`), and JVM/Tomcat (`0.2.3`) cannot be done by stuffing every runtime into one fat binary, nor by bolting unmanaged external daemons onto a Python supervisor. Every backend obeys five rules:

1. **P1 — One Supervisor Lifecycle, Two Privilege Regimes (`blastit` vs `blastit dev` / `check`).**
   Spawning, configuring, health-checking, instrumenting, logging, and supervising a runtime lives in `init` (`stage0` preflight + `stage1`/`supervise`; `supervise.rs` is the sole reaper of supervised children, while `visibility::reap` waits only on its own short-lived probe child). Throughout this design, **`<slot>` denotes `<uid>` (`UID_BASE + 1000 + i`) in `Production` (`/run/blastit/views/<uid>`, `config::view_dir`, `ARCHITECTURE.md` §2.2) and `<route_index>` in `Dev`/`Check` (`<root>/views/<index>`, `dev_learn.rs:126`)**. Production (`blastit`) and local/CI (`blastit dev`, `blastit check`) execute the **exact same spawn and teardown path**, differing only in the explicit `ADR-0001` dev simulation delta (§5.2): `dev`/`check` run under `geteuid()` inside an ephemeral `0700` `<runtime>` root, skipping `setresuid`/`setresgid`/`setgroups`, `chown`, and per-UID `RLIMIT_NPROC` while **keeping** Stage-0 `execve` secret stripping + `ALWAYS_STRIP`, per-route `<runtime>/views/<slot>` proxy socket directories, per-backend `SeccompRole` (`EmbeddedView { egress }` for PHP, `View { egress }` for WSGI/Node/JVM — both denying `setsid`/`setpgid`/`CLONE_NEW*`), `PR_SET_NO_NEW_PRIVS`, `RLIMIT_NOFILE`, `RLIMIT_CORE=0`, `umask 077`, the 3-line `unprivileged-dev` banner, and loopback-only binding (`127.0.0.1`, `--host` gated on `BLASTIT_DEV_EXPOSE=1`). **Blastit has zero unmanaged/external backend modes:** if Blastit cannot own and sandbox the runtime, it refuses to boot.
2. **P2 — Manifest Names *What the App Is*; Provider Owns Transport & Runtime Config.**
   `blastit.toml` declares application identity (`app = "module:attr"`, `[route.static] root = "public"`, `[route.php] entry = "public/index.php"`, `[route.node] entry = "build/index.js"`, `[route.jvm] entry = "target/app.jar"`). Blastit owns every transport endpoint (`view.chan` `socketpair`, reverse-accept `<runtime>/pools/<slot>/accept.sock`), `BLASTIT_FRAME_MAX` credit windows, `max_requests` recycling, and generated runtime configs inside `<runtime>` — never inside `manifest_dir` (`ProtectSystem=strict` and `readOnlyRootFilesystem: true` work everywhere). `[route.fastcgi]`, `listen`, `socket`, `port`, and `env` do not exist in `blastit.toml` (unknown-key boot errors).
3. **P3 — Uniform Boot-Time Runtime Discovery (Candidate List + One `BLASTIT_<RUNTIME>` Override).**
   Each provider declares an ordered candidate list — multi-arch library directories for shared objects (`libphp8.4.so`..`libphp.so`), `PATH` for executables (`node`/`nodejs`, `java`) — plus **one** environment override (`BLASTIT_LIBPHP`, `BLASTIT_NODE`, `BLASTIT_JAVA`), validated **once in Stage 0 before any listener binds**. Neither `LD_LIBRARY_PATH` nor manifest keys select a runtime. A host without a usable runtime gets a Stage-0 boot refusal naming the distro package and env override — never a degraded fallback. Resolved paths, versions, and derived ceilings appear in structured `boot` logs.
4. **P4 — Parallelism Belongs to the Scheduler; Provider Capacity Is a Ceiling.**
   `blastit-scheduler` is the single admission authority (`BLASTIT_MAX_WORKERS` global, `BLASTIT_VIEW_MAX_WORKERS` per route). Where a route accepts an optional downward `workers` cap (`[route.php]`, grammar bound `1..=64` at parse time and runtime bound `1..=view_worker_cap()` at Stage 0, defaulting to `view_worker_cap()`), `workers > view_worker_cap()` is a boot error naming both numbers, and every executor's `provider_ceiling` (`Upstream::capacity().max_concurrent`) must satisfy `provider_ceiling >= route_allocation` (under-provisioning aborts boot). No worker or runtime runs a second admission queue.
5. **P5 — In-Runtime CPU Instrumentation With Unforgeable Process-Wide Kernel Bounds.**
   Because Blastit owns every runtime, every runtime measures CPU internally (`CLOCK_THREAD_CPUTIME_ID` in WSGI/Static/JVM, `CLOCK_PROCESS_CPUTIME_ID` in embedded PHP, `async_hooks` + thread CPU in Node) and reports via `RESP_END_COST` / `CostReport`. Because a route worker executes untrusted app code, `Scheduler::charge` bounds every report below uniformly across all worker backends by process-wide kernel `/proc` CPU (`max(sum(pgrp_tasks_schedstat), /proc/<pid>/stat utime+stime+cutime+cstime)`, failing closed to `ceiling` when `/proc` is hidden) and above by `ceiling = observed_wall_ns * live_threads`, adds `scheduler_cpu_ns`, and debits `fair.rs`'s sticky virtual-CPU queue.

## 2. Goals, Non-Goals & Requirements (`R1..R25`)

**Goals:** Fix one coherent `SpawnSpec` + `Upstream` + `WorkerRuntime` architecture across Static, WSGI, PHP (embedded `libphp` only), Node/Vite SSR, and JVM/Tomcat; keep ingress, routing, `SeccompRole::Scheduler` (zero `socket()`), fair queuing, secret stripping, capability brokers, and `--learn`/`check` 100% shared; fix the `0.2.x` Linux `{x86_64, aarch64} × {glibc, musl}` platform/artifact matrix; and align `MB.2`–`MB.5` and `MB.9`.

**Non-Goals:** Designing `MB.4.1`'s N-API vs JS-bootstrap benchmark details (bounded here, decided in `MB.4.1`); supporting any FastCGI/`php-fpm` fallback, legacy non-12-factor apps (WordPress, `.htaccess`), macOS/Windows, or bundled runtimes inside `blastit`.

## 3. Ownership Taxonomy & Shared Pipeline

### 3.1 Three Provider Kinds (Zero Unmanaged Fallbacks)

### 3.2 What Never Varies vs What Varies

Every request traverses the **identical pipeline**: `blastit-http` (HTTP/1.1 parse, header/body/timeout limits, `BLASTIT_TRUSTED_PROXIES` IP resolution, `WINDOW` credits) → `blastit-scheduler` (`RoutingTable`, `blastit-ingress` / MC `blastit-wasm` body gate, `fair.rs` virtual-CPU admission queue, `BLASTIT_MAX_WORKERS` budget, `ResponseSink` header sanitization, `http_obs.jsonl`) → **`Arc<dyn Upstream>`** → route worker → **`<runtime>/views/<slot>/.s.PGSQL.<port>`** (`0600` + `SCM_CREDENTIALS`) → `blastit-dbproxy` (`WireSqlObs`, SQL policy, upstream TLS). Blastit never adds a second client-facing HTTP parser, admission queue, or audit path (for `MB.4`/`MB.5`, Node and Tomcat parse only the canonical HTTP/1.1 bytes written by `HttpUpstream`, `m11-R6`).

### 4.1 Worker-Side Contract: `WorkerRuntime` (`crates/blastit-view/src/runtime.rs`, proposed `MB.3.23`/`MB.3.24`)

`MB.3.11` (`done`, committed `90056a7`) gated PyO3 behind `feature = "python"`; proposed sibling leaves **`MB.3.23`** (trait + types, `depends_on: [MB.3.11]`) and **`MB.3.24`** (`WsgiRuntime` extraction + `critical_view_transport.rs`, `depends_on: [MB.3.23]` — verified free via `plan.py show` so closed `MB.3.11` and existing `MB.3.20`–`MB.3.22` stay untouched) decouple `blastit-view`'s `view.chan` `RawFrame` loop behind `WorkerRuntime`, using **`blastit_frame::{ReqHead, RespHead, DoneOutcome}` directly** plus `OutputStream` in `blastit-view/src/runtime.rs` while keeping **`blastit-view` `#![forbid(unsafe_code)]`**:

```rust
use blastit_frame::{DoneOutcome, ReqHead, RespHead};

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum OutputStream { Stdout, Stderr }

    /// "wsgi" or "php" (diagnostics and conformance keys only; never logged per request).
    fn kind(&self) -> &'static str;

    /// Blocking execution on the transport's request thread (`&self`: WSGI attaches GIL;
    /// `PhpEmbedRuntime` wraps its `blastit_php_sapi` handle inside a `Mutex` in `blastit-php-sapi`,

    fn serve(&self, req: ReqHead, io: &mut dyn RequestIo) -> RequestEnd;
    /// True when this worker must exit after `serve` (`max_requests` reached or fatal Zend bailout).
    fn recycle(&self) -> bool;
}

pub struct RequestEnd {
    pub outcome: DoneOutcome,
    pub cpu_ns: Option<u64>,
}
```

`RequestIo` (defined in `blastit-view/src/runtime.rs`) exposes `head() -> &ReqHead`, credit-paced `read_body(&mut [u8]) -> io::Result<usize>`, `write_head(RespHead) -> io::Result<()>`, credit-paced `write_body(&[u8]) -> io::Result<()>`, `output(OutputStream, &str)` (2048-byte line cap), and `flush_response() -> io::Result<()>`. `WorkerRuntime` contains **zero** `Python<'_>` tokens.

### 4.2 Scheduler-Side Contract: `Upstream` (`ADR-0008` Decision 1 + `ADR-0009`) & Crate DAG

`crates/blastit-backend` defines `pub trait Upstream` (`kind`, `capacity`, `ensure_ready`, `signal`, `plan`, `exchange`) with `ADR-0009`'s three additions (to be synced into `MB.9.1`'s brief before dispatch):
1. `ExchangeOutcome::Answered` carries `pub cost: Option<CostReport>` where `CostReport { pub cpu_ns: u64, pub source: CostSource }` and `#[serde(rename_all = "snake_case")] pub enum CostSource { ProcessExact, ThreadExact, AsyncContext, KernelFloor, Ceiling }`. `ViewUpstream` derives initial `source` from its `kind()` (`"php"` → `ProcessExact`, `"wsgi"` → `ThreadExact`), while `Scheduler::charge` upgrades `source` to `KernelFloor` when `kernel_floor_ns > reported_cpu_ns.min(ceiling)` and to `Ceiling` (`"ceiling"`) when `/proc` is unreadable (`hidepid=2`).
2. `ResponseSink` exposes `fn debit_cpu(&mut self, _delta_ns: u64) {}` for streaming/WebSocket reconciliation.
3. `conformance::PeerScript` uses protocol-neutral `status: u16` + `raw_head_override: Option<&'static [u8]>`.

**Acyclic Workspace Crate Dependency DAG & Feature Forwarding (MSRV `1.88`):**
- `blastit-backend` → `{blastit-http, blastit-manifest, serde}` (never depends on `blastit-view` or `blastit-scheduler`).
- `blastit-view` → `{blastit-frame, optional pyo3 (feature "python"), optional blastit-php-sapi (feature "php")}` (`#![forbid(unsafe_code)]`; never depends on `blastit-backend` or `blastit-scheduler`).
- `blastit-scheduler` → `{blastit-backend, blastit-frame, blastit-http, blastit-ingress, blastit-manifest}` (defines `ViewUpstream`, `ViewBuilder`, `StaticBuilder`, `ViewSet`).
- `blastit` (composition root, `features.php = ["blastit-view/php", "dep:blastit-php-sapi"]`) → `{blastit-backend, blastit-scheduler, blastit-view, optional blastit-php-sapi, blastit-env, blastit-sys, blastit-manifest, blastit-http, blastit-frame, blastit-events, blastit-dbproxy}`.

**One `ViewUpstream` serves both WSGI and Embedded PHP (`MB.9.3`, `MB.9.5`):**

| `Executor` | `kind()` | Builder | `Upstream` Impl | Worker `WorkerRuntime` | `ViewSet` Shape |
|---|---|---|---|---|---|
| `Executor::View` | `"wsgi"` | `ViewBuilder::wsgi()` | `ViewUpstream` | `WsgiRuntime` | `1` worker, `max_inflight = view_worker_cap` |
| `Executor::Php(PhpPolicy)` | `"php"` | `ViewBuilder::php()` | `ViewUpstream` | `PhpEmbedRuntime` | `1..=workers` workers, each `max_inflight = 1` |

`SessionPort::open(route)` selects an idle worker in `ViewSet` (`inflight < worker.max_inflight`), while `ViewUpstream::ensure_ready` asks `init` (`Ctl::Spawn`) to fork another PHP worker whenever admitted load exceeds idle PHP workers and `live_workers < route_allocation` (respecting `BLASTIT_MAX_VIEW_PROCESSES`, `docs/reference/settings.md:112`, and `BLASTIT_MEM_HIGH_WATERMARK`). Request dispatch calls `plan` + `exchange` on `Arc<dyn Upstream>` and **never** branches on `kind()`. Because no FastCGI backend exists, `SeccompRole::Scheduler` keeps its strict `0.2.0` filter (**zero `socket()` allowed**).

**Reverse-Accept `HttpUpstream` Canonical Contract (`MB.4` Node / `MB.5` JVM, `B3-R5`, `M1-R6`–`M3-R6`, `m9`/`m10-R6`):**
1. **Zero-`socket()` transport (`M1-R6`, `M2-R6`):** Stage 0 (`init`) binds one `AF_UNIX` `UnixListener` per `Managed` route at `<runtime>/pools/<slot>/accept.sock` (`0700` dir / `0600` socket owned by `route_uid`, `SO_PASSCRED` **unset**) and passes the listening fd to `scheduler` across fork. `scheduler` calls `accept4(SOCK_CLOEXEC)` (which requires **zero `socket()` syscall**, preserving `SeccompRole::Scheduler` unchanged!) while the `Managed` worker (`node-worker.mjs` / `blastit-jvm-agent`) maintains ready outbound `connect()` streams, serving **one** `Connection: close` exchange per accepted stream and immediately re-`connect()`ing. `HttpUpstream` reads exclusively with plain `read(2)`/`recv(2)` (no `msg_control`, so worker `SCM_RIGHTS` fds can never enter `scheduler`, `M2-R6`).
2. **Request canonicalization (`B3-R5`, `M3-R6`):** `HttpUpstream` serializes a fresh HTTP/1.1 request from parsed `UpstreamHead`: origin-form target only; **exactly one** synthesized `Host` from `head.server_name`; **mutually exclusive framing** (buffered: single `Content-Length: <n>`, zero `Transfer-Encoding`; streamed: `HttpUpstream`-encoded `Transfer-Encoding: chunked`, zero `Content-Length`) + `Connection: close` (`Expect: 100-continue` handled at `blastit-http` front end and stripped before `HttpUpstream`, `m10-R6`); all hop-by-hop headers **plus the entire forwarded/spoof family (`Forwarded`, `X-Forwarded-For`, `X-Forwarded-Proto`, `X-Forwarded-Host`, `X-Forwarded-Port`, `X-Forwarded-Prefix`, `X-Forwarded-Server`, `X-Real-IP`, `X-Original-URL`, `X-Rewrite-URL`, `Client-IP`, `True-Client-IP`) stripped**, then `X-Forwarded-For` and `X-Forwarded-Proto` written solely from `head.remote_addr` and `head.scheme` (`M3-R6`); RFC 9110 `tchar` names and CTL-free values enforced.
3. **Response parsing (`m9`/`m10-R6`):** `HttpUpstream` parses the worker's response with strict RFC 9112 rules: rejects `100`–`199` (including `101 Switching Protocols` -> `502` `Fault`), `CL`+`TE`, duplicate `CL`, obs-fold, non-`tchar` names, CTL values, and the four forbidden proxy-control headers (`X-Accel-Redirect`, `X-Sendfile`, `X-Lighttpd-Send-File`, `X-Rewrite-URL` -> `502` `Fault`), and suppresses body reads on `HEAD` before passing chunks to `ResponseSink`. Covered by `critical_http_upstream_smuggling.rs`.

### 4.5 Verified CPU Fair Queuing (`Scheduler::charge` + `fair.rs`)

```text
total_charged_ns = scheduler_cpu_ns.saturating_add(bounded_worker_ns)
```

1. **Scheduler-Side CPU (`scheduler_cpu_ns`, `S15`):** Measured via `CLOCK_THREAD_CPUTIME_ID` around synchronous head normalization, routing, ingress decoding/re-encoding, and response framing **plus** inside any `spawn_blocking` slice (`StaticUpstream` `pread`), summed into `scheduler_cpu_ns`.
2. **Worker Measurement:** `PhpEmbedRuntime` reads `CLOCK_PROCESS_CPUTIME_ID` around `php_request_startup`..`php_request_shutdown` (including `fastcgi_finish_request()` post-response work); `WsgiRuntime` reads `CLOCK_THREAD_CPUTIME_ID`; `StaticUpstream` reads `CLOCK_THREAD_CPUTIME_ID` around `pread` (`cpu_ns` on `request` event remains `null`); `NodeProvider` / `JvmProvider` (`MB.4`/`MB.5`) read `AsyncLocalStorage` + thread CPU / `ThreadMXBean.getCurrentThreadCpuTime()`.
3. **Anti-Forgery Bounds (`B3`, `M12`, `m16`, `S4`, `S5`, `S9`, `S12`, `K1`, `M5`, `M1-R4`, `M6-R4`, `M2-R5`, `M7-R5`, `M2-R6`, `M6-R6`, `m8-R6`):**
   - Both `view.chan` and `HttpUpstream` streams are read with plain `read(2)`/`recv(2)` (`SO_PASSCRED` never set, zero `msg_control` buffer so `SCM_RIGHTS` fds can never enter `scheduler`, `M2-R6`; `dbproxy` parses `SCM_CREDENTIALS` only and immediately closes any `SCM_RIGHTS` fds via `MSG_CMSG_CLOEXEC`, `m8-R6`). `RESP_END_COST` payload must be `9` (`cpu_present == 0`) or `17` bytes (`cpu_present == 1`), valid at most once per active `req_id` immediately before `DONE` (else `Fault` + worker recycle), and **`RESP_END_COST`'s wire `wall_ns` field is ignored** (`S9`).
   - **Dynamic Thread Multiplier & Ceiling (`S12`, `M5`, `M6-R6`, `M1-R7`):** Uniformly across **all** worker backends (**PHP, WSGI, Node, and JVM**), `max_threads` is live `/proc/<pid>/status` `Threads:` (clamped into `1..=rlimit_nproc`, fallback **`rlimit_nproc`** in `Production` and `max_workers` in `Dev` when `/proc` is hidden, emitting `Warning::ProcUnreadableCeilingFallback`); `ceiling = observed_wall_ns.saturating_mul(max_threads)`.
   - **Process-Wide & Group-Wide Kernel Floor (`kernel_floor_ns`, `S4`, `K1`, `M1-R4`, `M2-R5`, `M1-R7`):** Uniformly across **all** worker backends, `kernel_floor_ns` is **`max(sum(pgrp_tasks_schedstat), /proc/<worker_pid>/stat utime+stime+cutime+cstime)`** — capturing PHP C-extension helper threads (`M1-R7`), WSGI/Node/JVM threads, joined threads (`utime+stime`), reaped children (`cutime+cstime`), and live forked children inside `-pgid`! **If `/proc` is unreadable (`hidepid=2` without `gid=<scheduler_gid>`), `kernel_floor_ns` fails closed to `ceiling` (`cpu_source: "ceiling"`)**.
   - **Injectable `ProcSource` Seam (`M3-T1`, `M4-T1`):** `blastit-scheduler` defines `pub trait ProcSource: Send + Sync` (`read_threads(pid) -> io::Result<u32>`, `read_pgrp_schedstat(pid) -> io::Result<u64>`, `read_stat_ticks(pid) -> io::Result<u64>`) injected into `Scheduler` (`OsProcSource` in prod/dev, deterministic fake in `critical_fair_cpu.rs`). `MB.9.3` **removes** the superseded first-frame floor in `crates/blastit-scheduler/tests/fairness.rs:414,461,509` and replaces those assertions with `ProcSource`-backed CPU floor tests.
   - **Panic-Free Floor-Wins Formula (`M1-R4`):** `bounded_worker_ns = reported_cpu_ns.min(ceiling).max(kernel_floor_ns)`. On worker crash, `504` timeout, or protocol `Fault`, `bounded_worker_ns = ceiling.max(kernel_floor_ns)`.
4. **Sticky Virtual-CPU Queue & Streaming Reconciliation (`fair.rs`, `S5`, `K1`):** `(OuterFlow, InnerFlow)` virtual CPU `used` advances monotonically (`BLASTIT_FQ_BURST = 20ms`, `BLASTIT_FQ_MAX_DEBT = 5s`, `BLASTIT_FQ_DEBT_TTL = 30s`), never coupled to client `WINDOW` readback. Long-lived SSE/WebSocket streams reconcile scheduler-sampled process-wide `/proc` deltas every `250ms` (or outbound flush), bounded per interval by `dt.saturating_mul(max_threads)`. Exhausted flows deprioritize behind quieter flows (`503` + `Retry-After: 1` only on queue full/timeout).

**Boot Shim Selection, Native Build Strategy & Mandatory `musl` Security Gate (`MB.3.18`):**
> **Provenance of every count:** `scripts/platform_matrix.py` declares each leg and records what is **proved** (built *and* exercised); `make platform-matrix-check` refuses a document that over-claims either number. Declared `0.2.x`: `8` wheels, `4` archives, `12` shims. Proved: the x86_64 legs (`6` shims, `4` wheels, `2` archives in `MB.3.18`); the aarch64 legs build and probe natively in CI (`ubuntu-24.04-arm`) because a shim cannot be cross-compiled and no emulator can prove `seccomp`/`fork`. A leg that fails its probe is dropped with a recorded reason.

1. **Boot selection rule:** `blastit` pairs its compile-time `(target_arch, target_env)` (`x86_64`/`aarch64`, `gnu`/`musl`) with the host `libphp`'s probed `(major, minor, NTS)` to open `libblastit_php<major><minor>-<arch>-<libc>.so` (e.g. `libblastit_php84-aarch64-musl.so`, zero `DT_RPATH`/`DT_RUNPATH`); any missing/ZTS/unmatched tuple exits `1` (`check` `2`) naming `(PHP X.Y, <arch>-<libc>)`, the distro package, and `BLASTIT_LIBPHP`.
2. **Native builds & native execution probes (`MB.3.18`):** Never cross-compile against foreign `php_config.h` (build-specific type sizes, `ZEND_MM_ALIGNMENT`, and libc macros drift silently until `dlopen`). CI builds **and** runs the SAPI probe + `critical_shim_contract` + `critical_php_embed` natively on `x86_64` and `aarch64` runners (host for `gnu`, native-arch `alpine` containers for `musl`). **macOS and Windows are explicitly unsupported** (Linux-only UID/`openat2`/`SCM_CREDENTIALS`/`seccomp` sandbox; Homebrew PHP lacks `--enable-embed`; Windows embed ABI differs).
3. **`musl` Drop-Not-Degrade Security Gate (`ADR-0010` §4):** `musl` / Alpine ships **only** if all six invariants pass natively in `MB.3.18`: **(M-1)** Stage-0 `execve` swap + `BLASTIT_*` + `const ALWAYS_STRIP` leave zero secrets/hijacks in worker `environ`/heap; **(M-2)** per-route UID + `capset` zeroing + `SeccompRole::EmbeddedView` install cleanly with **zero silent filter widening**; **(M-3)** `AF_INET`/`AF_INET6` return `EPERM` when `egress = false`, and other routes' `0700` `/run/blastit/views/<other_uid>` dirs return `EACCES`; **(M-4)** `CLOCK_PROCESS_CPUTIME_ID` + `/proc` reconciliation work accurately (under `hidepid=2`, failing closed to `rlimit_nproc * wall` logged as `cpu_source: "ceiling"`); **(M-5)** signed Alpine `php84-embed` `dlopen("/proc/self/fd/<libphp_fd>", RTLD_NOW | RTLD_GLOBAL)` + shim `RTLD_NOW | RTLD_LOCAL` resolves cleanly with zero `DT_RUNPATH` into writable dirs and native musl shims (`musl`'s no-op `dlclose` is isolated inside the `_exit`ing Stage-1 probe child); **(M-6)** `ffi.enable=0`, `opcache.preload=`, `register_argc_argv=0`, `phar.readonly=1`, `phar.require_hash=1`, `disable_functions` (including `putenv` and `posix_kill`), `memory_limit=256M`, isolated `bt_getenv`, absolute `include_path=<manifest_dir>`, `plain_is_protected` on `/usr/lib/php84/modules` **and every loaded `.so` file**, read-only `manifest_dir`, and the full `e2e/php2shell.py` (`+ phar://` control) suite pass on Alpine (`M6-R5`). ## 5. Security & CVE Analysis

### 5.1 Threat Boundaries, Stage-1 Heap Purity & `.env` Scope (`B2`–`B4`, `M5`–`M9`, `S1`–`S12`, `K1`–`K3`, `M1`–`M9`)

1. **Stage-0 Core/Dump Guard, Secret Barrier & Post-Barrier Probe (`M8`, `S2`, `M3`, `M4`, `M8-R5`, `B2-R5`):** Stage 0 sets `RLIMIT_CORE = 0` and `prctl(PR_SET_DUMPABLE, 0)` at entry **before** reading any secret (`M8-R5`); real `[proxy.*]` credentials live only in Stage-0 `Zeroizing` buffers written once to `dbproxy`'s pipe and dropped before Stage 0 `execve`s Stage 1. Stage 0 performs **only** `stat`/`open` + `plain_is_protected` + `!has_file_caps` checks on runtimes, shims, `<runtime>/bootstrap/*`, interpreter prefixes, and pre-scanned PHP `.ini` / `extension_dir` / `extension=` / `zend_extension=` targets, **and verifies `manifest_dir`, `entry`, and `static.root` are non-writable by any route UID/GID in `Production` (`B2-R5`)**, recording `(path, st_dev, st_ino)` in Stage-1 `Config`. Stage 1 re-opens each `O_RDONLY | O_CLOEXEC | O_NOFOLLOW`, verifies `fstat` matches Stage 0's `(st_dev, st_ino)`, passes `OwnedFd` via `ChildIo.keep`, and runs the contained `-pgid` `libphp` probe **before** `bind_tcp(0.0.0.0:$PORT)` via `/proc/self/fd/<N>` (`check` runs `Host::stage1()`'s inode-verified `Reexec` `--role=php-probe` with `env = {}`).
2. **App-Held Secrets, `AF_UNIX` DAC & Pre-Milestone-C `raw` Body Scope (`M6`, `S7`, `B1-R5`, `M6-R3`, `M8-R3`):**
   - Secrets that app code reads from disk or non-proxied env vars (`.env`, framework signing keys) sit inside the route's trust domain (`docs/security.md` `#what-a-compromise-gets`); in `Production`, `manifest_dir` and `static.root` are read-only to route UIDs (`B2-R5`). Classic seccomp BPF filters `socket(AF_UNIX)` by family rather than `connect(2)` pathnames (`B1-R5`), so other routes' `0700` `/run/blastit/views/<other_uid>` sockets are protected by DAC (`EACCES`) and single-app containers must never mount host control sockets (`docker.sock`, D-Bus, systemd).
   - Pre-Milestone-C `raw` bodies reach backend parsers un-CDR'd: on PHP, `phar.readonly=1` + `phar.require_hash=1` block unsigned phars and creation, **but a hash-signed malicious `.phar` still executes if the PHP app itself `include`s/`unserialize`s an attacker-controlled upload path (`M8-R3`)** — Milestone C's WASM CDR strips polyglots before PHP sees them. ## 6. Alternatives Considered

| Rejected Alternative | Invariant Broken |
|---|---|
| **1. Bundle CPython, `libphp`, Node, and OpenJDK into one binary** | Breaks Apache-2.0 licensing (`PHP-3.01`, `GPL-2.0-CE`), bloats archive by >300 MiB, breaks distro NTS C extensions, and couples weekly runtime CVEs to Blastit releases. |
| **2. Keep `libpython` or `libphp` in `blastit`'s `DT_NEEDED`** | Breaks zero-prerequisite static/Node/JVM hosts (`ld-linux.so` aborts before `main()`). |
| **3. Pure-Rust `dlopen("libphp.so")` without per-minor C shims** | `sapi_globals_struct` and `EG(bailout)` offsets shift per PHP minor (`8.2` vs `8.4`, **R§2**), causing `SIGSEGV` on `exit()`. |
| **4. `php-fpm` + FastCGI (as primary or as external fallback)** | Managed FPM adds bind-window TOCTOU machinery and widens scheduler seccomp; external FPM forfeits Stage-0 secret stripping, per-route `dbproxy` grants, and exact CPU accounting while splitting docs/tests across two PHP models. |
| **5. Clamp worker CPU below by `dispatch -> first_frame` or leader-only `schedstat`** | Compromised worker sends `RESP_HEAD` early or burns CPU on a non-leader pool thread, reports `0`, and starves honest flows (`B3`, `K1`). |
| **6. Shared pre-fork OPcache SHM across PHP workers in `0.2.1`** | Risks SysV semaphore (`semget`) seccomp refusals and lets one compromised worker corrupt sibling workers' writable bytecode cache (§4.4). |
| **7. PID-1 JS `init()` addon wrapping Blastit inside `node` (`MB.4.1`)** | `/proc/1/environ` and V8 heap retain raw platform secrets before `init()` runs and parser shares app address space; `blastit` must always be Stage 0. |

### 9.2 What Implementation Must Prove (Test-Only Invariants & Open Questions)

1. **Pre-startup INI & `extension_dir` ordering (`MB.3.12`/`MB.3.13.3`):** `ZEND_INI_SYSTEM` pins (`ffi.enable=0`, `opcache.preload=`, `allow_url_fopen=0` when `!egress`) and Stage-0 `.ini`/`.so` `plain_is_protected` checks reject hostile configs *before* `php_module_startup` executes any extension `MINIT`.
2. **`egress = true` + `allow_url_fopen=1` vs `egress = false` (`MB.3.13.3`/`MB.3.26`/`MB.3.7`):** Non-egress PHP routes fail outbound TCP with `EPERM` and `allow_url_fopen=0`; `egress = true` emits `ManifestWarning::EgressRoute` (and refuses under presets without `BLASTIT_ALLOW_EGRESS=1`).
3. **Subreaper, pre-filter `setpgid(0, 0)` & `WNOWAIT` ordering (`MB.3.26`):** Immediate-exit children and `fork()`ed grandchildren are reaped to `0` survivors on both Linux and gVisor without racing generic `waitpid(-1)` or signalling `init`'s pgid.
4. **Process-wide tick/schedstat floor (`MB.9.3`/`MB.9.5`):** Threaded/forked workers burning CPU on non-leader tasks while reporting `0` are charged `>= actual CPU` via `max(pgrp_schedstat, stat)`.
5. **Native per-platform shim ABI & `(M-1)`–`(M-6)` `musl` gate (`MB.3.12`/`MB.3.18`):** Every shipped `libblastit_php<minor>-<arch>-<libc>.so` passes the Stage-1 probe and `make platform-matrix-check` natively on its target, dropping any unproven minor or failing `musl` leg with a recorded 1-line reason.
6. **Implementation-time questions for `MB.3.13`/`MB.3.16`/`MB.3.18`:** (a) exact ELF `.dynsym` parser layout for multi-arch `gnu`/`musl` `libphp` (`MB.3.13.3`); (b) Python-less `check` summary rendering when all routes are `Static` (`MB.3.16`); (c) whether Alpine `php82-embed`/`php83-embed` community packages exist on `3.21` or are recorded `dropped` with a reason in `scripts/platform_matrix.py` (`MB.3.18`).
