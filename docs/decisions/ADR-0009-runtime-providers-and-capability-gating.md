# ADR-0009: Runtime Providers, Capability-Gated Python, CPU Fair Queuing & Distribution

- **Status:** Accepted — Superseded in part by ADR-0016 (Decision 1's `WorkerRuntime`/`Upstream` trait requirement and its `setpgid(0,0)` sentence, Decision 2's `Upstream::capacity()` parenthetical, and Decision 5's distribution command spelling and wheel feature list; everything else stands)
- **Date:** 2026-11-14
- **Node:** MB.12 (amends Decision 1 of [ADR-0008](ADR-0008-fastcgi-backend-and-param-lockdown.md); paired with [ADR-0010](ADR-0010-php-embedded-via-libphp-embed.md))
- **Owner:** architect

## Context

Blastit `0.1.1` coupled its supervisor and worker transport to embedded CPython (`blastit-view` / `pyo3`), while early `0.2.x` drafts either forced non-Python projects to install Python wheels (`static-and-spa.md`), leaked daemon socket wiring into user workflows (`ADR-0008`), or charged wall-clock time rather than verified CPU time in `fair.rs`. Serving Static, Python WSGI, PHP (`ADR-0010`), Node/Vite SSR (`MB.4`), and JVM/Tomcat (`MB.5`) requires separating the shared invariant pipeline (`blastit-http`, `blastit-ingress`, `blastit-scheduler`, `blastit-env`, `blastit-dbproxy`, `--learn`/`check`) from per-runtime ownership (`SpawnSpec` + `WorkerRuntime`), enforcing fail-closed production boundaries with zero degraded external modes, and deriving distribution artifacts from binary linkage.

**Decision chain:** `ADR-0008` (contributes **only** the `Upstream` dispatch contract; all FastCGI content superseded) → **`ADR-0009`** (runtime-provider & worker contract, capability gating, CPU fair queuing, distribution) → [`ADR-0010`](ADR-0010-php-embedded-via-libphp-embed.md) (embedded NTS `libphp.so` as the sole PHP backend over `view.chan`).

## Decision

1. **Dual Seam (`Upstream` + `Option<SpawnSpec>` / `WorkerRuntime`), Three Provider Kinds & One Dev/Prod Lifecycle.**
   Every backend pairs a scheduler-side `blastit_backend::Upstream` (`StaticUpstream`, language-agnostic `ViewUpstream` over `view.chan` serving WSGI and PHP, and `MB.4`/`MB.5` reverse-accept `HttpUpstream`) with a composition-root `Option<SpawnSpec>` (`supervise.rs` remains the sole reaper of supervised children) across exactly three `ProviderKind`s: **`Embedded`** (`Some(SpawnSpec)`: `WsgiRuntime` under `SeccompRole::View`, `PhpEmbedRuntime` under `SeccompRole::EmbeddedView` behind `blastit_view::WorkerRuntime`), **`Managed`** (`Some(SpawnSpec)` with `WorkerBinding::{Node, Jvm}` under `SeccompRole::View`), or **`None`** (`None`: `StaticUpstream` spawns nothing). Stage 0 sets `RLIMIT_CORE=0` and `PR_SET_DUMPABLE(0)` before reading secrets, and requires `manifest_dir`/`entry`/`static.root` to be non-writable by route UIDs in `Production`. Both `View` and `EmbeddedView` deny `setsid` (`EPERM`), `setpgid` (`EPERM`), `clone3` (`ENOSYS`), and `clone(CLONE_NEW*)` (`EPERM`), while `EmbeddedView` also denies `execve`, `execveat`, `fork`, `vfork`, and non-`CLONE_THREAD` `clone` (`EPERM`). Single-threaded `init` (`SignalFd`, `PR_SET_CHILD_SUBREAPER(1)`) places each child into `setpgid(0, 0)` before filter install and withholds leader reaping via gVisor-compatible `waitid(P_PID, WNOWAIT)` ordered before generic `reap()` until `getpgid(pid) == pid` + `kill(-pid, SIGKILL)` complete. Every backend runs **one spawn/supervise/teardown code path** across `blastit` and `blastit dev` / `check` (`ADR-0001`). **Blastit supports zero unmanaged/external backend fallbacks.**
2. **Manifest Minimalism, Provider-Owned Transport, Scheduler-Owned Parallelism & Runtime Discovery.**
   - `blastit.toml` declares *what the app is*: `app = "module:attr"`, `[route.static] { root, index, spa, immutable }`, `[route.php] { entry, workers? }` (`workers` parse bound `1..=64`), `[route.node] { entry }`, `[route.jvm] { entry }` (`[route.fastcgi]`, `listen`, `socket`, `port`, `env` are unknown-key boot errors). All Blastit-owned channels (`view.chan` `socketpair`, reverse-accept `<runtime>/pools/<slot>/accept.sock`) and configs live under `<runtime>` (never in `manifest_dir`, compatible with `ProtectSystem=strict`).
   - `blastit-scheduler` is the sole admission authority (`BLASTIT_MAX_WORKERS`, `BLASTIT_VIEW_MAX_WORKERS`); any optional route `workers` cap is strictly downward (`1..=64` at parse time and `<= view_worker_cap()` at Stage 0, over-budget refused at boot), and executors must satisfy `provider_ceiling >= route_allocation` (`Upstream::capacity().max_concurrent`).
   - Runtime discovery uses an ordered candidate list plus **one** env override (`BLASTIT_LIBPHP`, `BLASTIT_NODE`, `BLASTIT_JAVA`), validated once in Stage 0 before binding listeners. In `Production`, resolved libraries/binaries, Blastit shims, `PYTHONHOME` (on `Install::Wheel`), and pre-scanned PHP `.ini` / `extension_dir` / `.so` targets must pass `host::plain_is_protected(path, init_uid)` + `!has_file_caps(path)` with `(st_dev, st_ino)` recorded in `Config` and re-verified before `/proc/self/fd/<N>` load/exec. Resolved paths and derived ceilings appear in structured `boot` logs (`"runtimes"`).
3. **Per-Route Sandbox Bijection & Memory Honesty.**
   Every route with an executor gets `UID_BASE + 1000 + i` (`gid == uid`) and `/run/blastit/views/<uid>` (`config::view_dir`) in `Production`, and `<root>/views/<index>` in `Dev`/`Check` (`<slot>`). Two routes never share a worker UID with differing `[proxy.*]` grants or `egress` (presets refuse `egress = true` unless `BLASTIT_ALLOW_EGRESS=1`, owned by proposed `MB.3.26` & `MB.3.10`). Non-CoW runtimes (Node ~45–90 MiB/route, JVM ~150–350 MiB/route) rely on lazy spawn + `BLASTIT_MEM_HIGH_WATERMARK` eviction and coarse trust-domain routes.
4. **Verified CPU Fair Queuing (Amends `ADR-0008` Decision 1).**
   - Runtimes measure CPU internally (`CLOCK_THREAD_CPUTIME_ID` in WSGI/Static/JVM, `CLOCK_PROCESS_CPUTIME_ID` in PHP, `async_hooks` + thread CPU in Node) and report via `RESP_END_COST` (`ExchangeOutcome::Answered` gains `cost: Option<CostReport { cpu_ns, source }>`, where `CostSource` has `ProcessExact`, `ThreadExact`, `AsyncContext`, `KernelFloor`, and `Ceiling`; `ResponseSink` gains `debit_cpu(u64)`; `PeerScript` uses `status: u16`).
   - **Panic-free process-wide anti-forgery charge:** For **every** worker backend (PHP, WSGI, Node, and JVM uniformly), `max_threads` is live `/proc/<pid>/status` `Threads:` (`1..=rlimit_nproc`, fallback `rlimit_nproc` in `Production` and `max_workers` in `Dev` under `hidepid=2` with `Warning::ProcUnreadableCeilingFallback`); `ceiling = observed_wall_ns.saturating_mul(max_threads)` (wire `RESP_END_COST.wall_ns` is ignored). Kernel floor `kernel_floor_ns` is **`max(sum(pgrp_tasks_schedstat), /proc/<pid>/stat utime+stime+cutime+cstime)`** for all worker backends (so any extension thread in PHP or worker thread/child in `View` is captured); if `/proc` is unreadable (`hidepid=2` without `gid=<scheduler_gid>`), `kernel_floor_ns` **fails closed to `ceiling`** (`cpu_source: "ceiling"`). For valid reports, `bounded = reported_cpu_ns.min(ceiling).max(kernel_floor_ns)`; on crash, `504`, or duplicate/invalid cost frame, `bounded = ceiling.max(kernel_floor_ns)`. Streaming `debit_cpu` reconciles scheduler-sampled process-wide `/proc` deltas every `250ms` (capped by `dt * max_threads`). `fair.rs` debits `scheduler_cpu_ns.saturating_add(bounded)` monotonically (`BLASTIT_FQ_BURST = 20ms`, `BLASTIT_FQ_MAX_DEBT = 5s`, work-conserving deprioritization, zero client-readback coupling).
5. **Honest `check` Completeness & Capability-Gated Distribution.**
   - Executor routes count in `routes.exercised` iff `>= 1` `wire_request` has `executor_ran == true`; `check::serve_and_run` binds a dedicated `<CheckRoot>/dev/fixture` (`ObsTarget::Fixture` in `blastit-dbproxy/src/learn.rs`, `Check`-only, `ENOENT` in `Production` & standalone `dev`) socket for `<suite>` so test-fixture SQL never pollutes Route 0.
   - Cargo feature `python` (`MB.3.11`, verified by `MB.3.15`/`MB.3.16`) yields two artifact families of **one program** across all four Linux **`{x86_64, aarch64} × {glibc, musl}`** targets (`ADR-0010` §4 / `MB.3.18`, with `musl` gated on `ADR-0010`'s 6-point security checklist): (a) standalone `blastit-{x86_64,aarch64}-unknown-linux-{gnu,musl}` (`--no-default-features --features php` + up to 3 proven `libblastit_php{82,83,84}-<arch>-<libc>.so` shims per `ADR-0010` §4's provenance rule, shipped as release tarballs, `ghcr.io/offworldnexus/blastit:php8.4{,-alpine}`, and `@blastit/cli` on npm) carrying **zero `libpython` and zero `libphp`**, refusing WSGI `app` cleanly at Stage 0 (`uv add blastit`); (b) PyPI wheels (`cp313`/`cp314` × `{manylinux_2_28, musllinux_1_2}` × `{x86_64, aarch64}`, `features = ["python", "php"]` + Python-free `blastit-dbproxy`).
   - **Proposed `ROADMAP.md` MB wording alignment for `strategist`:** update MB(3) from `PHP-FPM (FastCGI)` to `PHP (embedded NTS libphp SAPI)` and MB(4) to `Managed Node/Vite worker & SSR split`.

## Rejected Alternatives

- **Fat single binary bundling CPython/`libphp`/Node/JVM:** breaks Apache-2.0 licensing (`PHP-3.01`, `GPL-2.0-CE`, `LGPL`), distro extension ABIs, and independent CVE patching.
- **External `php-fpm` / unmanaged user servers (even as a fallback):** forfeits Stage-0 secret stripping, per-route `dbproxy` grants, and trusted CPU accounting, and doubles code/docs surface.
- **Clamping worker CPU reports below by `dispatch -> first_frame` or leader-only `schedstat`:** allows compromised multi-threaded or streaming workers to report `0` and starve siblings.

## Consequences

- **Positive:** One security model, one CPU-accounting model, fail-closed production, and Python-free standalone distribution across Static, PHP, Node, and JVM.
- **Trade-offs:** Requires `MB.3.11`/`MB.3.15` (`python` feature gate + capability tests), proposed sibling leaves `MB.3.23`/`MB.3.24` (`WorkerRuntime`), proposed `MB.3.25`/`MB.3.26` (`View`/`EmbeddedView` seccomp + subreaper + `BLASTIT_ALLOW_EGRESS`), and `CostReport` in `MB.9.1`.
